# DatabaseFacade 版本说明

## 2026-10-22 1.0.0 初始实现

- 新增数据库类型中立 C ABI 和内部 Provider 抽象工厂。
- 新增 PostgreSQL 连接池、参数化 SQL、批量事务、显式事务、预编译和结果字段复制能力。
- 新增连接池统计、健康检查和 ABI/依赖版本信息。

## 2026-10-22 1.0.1 连接池恢复语义补齐

- 数据库暂时不可用时允许池对象创建，由后台维护线程持续补足最小连接；首条连接建立前 readiness 保持未就绪。
- 使用“现有连接数加正在创建数”限制并发扩容，避免超过最大连接数。
- 实现空闲连接回收、物理连接健康检查、后台重连以及可等待的确定性停机。
- 统计新增后台重连成功数和空闲收缩数，便于区分业务获取、故障恢复和容量回收。

## 2026-10-22 1.0.1.0 发布元数据与目录规范

- Release 动态产物统一输出到 `lib/x64vc14/dynamic`，静态兼容产物继续输出到 `lib/x64vc14/static`。
- DLL 增加 `1.0.1.0` 文件版本和产品版本，版本号与本轮连接池恢复语义保持一致。
- V3 的 ClientData、Query 和 Trade 统一动态使用本 DLL，业务工程不得直接链接 pqxx 或 libpq。

## 2026-10-29 实现版本仍为 1.0.1.0 的工作树一致性复核

### 当前实际事务语义

- V3 的 `CPostgreSqlPool` 已成为 DatabaseFacade C ABI 适配层，不再直接包含或调用 pqxx/libpq。
- `DatabaseFacade_Execute` 和 `DatabaseFacade_ExecutePrepared` 当前仍以 `pqxx::work` 执行单条语句并显式
  `commit()`；`DatabaseFacade_ExecuteBatch` 和显式事务接口同样使用事务语义。
- 因此，V3 ClientData 专题中“普通单语句使用 `pqxx::nontransaction`，移除额外 BEGIN/COMMIT 往返”的
  描述目前不再对应本工作树实现，不能作为已完成的性能优化验收项。

### 验证与待办

- 静态核对已确认 V3 适配层调用 DatabaseFacade，且 DatabaseFacade 当前单语句路径存在
  `pqxx::work` 与 `commit()`。
- V3 旧的 ClientData 延迟门禁仍扫描迁移前的 `CPqxxConnectionAdapter`，当前执行失败；门禁和专题文档
  必须随最终事务策略一起修正。
- 本次只补版本说明，没有修改数据库执行语义、ABI 或二进制，也没有连接 PostgreSQL 进行性能回归。
