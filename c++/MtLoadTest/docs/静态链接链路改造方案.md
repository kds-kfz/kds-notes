# MtLoadTest 静态链接链路改造方案

## 目标

`MtLoadTest` 增加 `ReleaseStatic|x64`，把自研压测依赖和 xlnt 直接链接进 EXE；既有 `Release|x64` 保留动态链，便于需要独立升级 DLL 的部署方式。

## 调用边界

- `CLoadEngineClient` 仍是唯一引擎适配层。
- 动态配置继续通过 `LoadLibrary/GetProcAddress` 绑定稳定 C ABI。
- 静态配置通过 `MTLOADTEST_STATIC_STACK` 直接绑定同名 C ABI，不加载引擎 DLL。
- MFC 对话框不感知引擎内部类型和链接方式。

## 发布目录

- 动态版：`bin/x64vc14/share/MtLoadTest.exe`，部署 MtLoadEngine、SocketClient、xlnt 和 HPSocket DLL。
- 静态版：`bin/x64vc14/static/MtLoadTest.exe`，部署 EXE 和配置文件，不部署 HPSocket、自研库或 xlnt DLL。
- 两种版本都使用 `/MD`；静态版把自研库、xlnt 和 HP-Socket 直接链接进 EXE，动态版保持原 DLL 链。

## 验收

- 构建 SocketClient、xlnt、MtLoadEngine 和 MtLoadTest 的静态链。
- 检查静态 EXE 导入表，确认不导入 `MtLoadEngine.dll`、`libSocketClient.dll`、`HPSocket.dll` 和 `xlnt.dll`。
- 启动静态版并验证引擎 ABI、XML 检测、窗口关闭和线程回收。
- 回归动态构建，确保双模式没有互相引用错误目录。
