# MtLoadTest 界面设计方案

## 1. 状态与目标

本文描述当前 MFC 工具。应用采用“主入口 + 独立功能窗口”：压力测试及 HTTP/HTTPS/Web JSON 接口测试已实现；数据查看保留独立入口和占位窗口。压测参数编辑仍不属于 MFC 责任。

界面不拥有压测业务规则。即使将来改用 Qt、Python 或命令行，相同 XML、运行状态、指标和报告口径仍由动态库提供。

## 2. 应用主窗口

`CMainDlg` 是程序唯一主窗口，顶部菜单和三个命令按钮均提供以下入口：

- 压力测试：模态打开现有 `CMtLoadTestDlg`，关闭后回到主窗口。
- 接口测试：打开 `CInterfaceTestDlg`，使用 `MtLoadTest/conf/interface-test.xml`，不复用压测计划或 `MtLoadEngine/conf`。
- 数据查看：当前打开 `CReservedFeatureDlg` 占位窗口，明确后续支持 symbols、历史 K 线、双槽位与时间戳另存。

主窗口不加载 `MtLoadEngine.dll`。只有用户进入压力测试窗口后，该窗口才创建 DLL 适配器和日志对象；关闭压力测试窗口必须完整 Stop/Wait/Destroy/FreeLibrary，但应用主窗口继续存在。

## 3. 压力测试窗口布局

压力测试窗口采用“左侧配置、右侧操作、下方结果”的布局：

```text
+---------------------------------------------------------------+
| 计划文件：[只读 XML 路径]       | 浏览 | 加载 | 日志 | 导出  |
| 运行环境：[环境选择]            | 开始 | 暂停 | 清空         |
| 压测场景：[全部或一个中文场景]                              |
| 压测用户：[场景 UserRefs 或一个具体用户]                    |
| 状态：运行状态、已请求/总请求、活动用户、在途请求            |
+---------------------------------------------------------------+
| 指标列表：场景、步骤、接口、进度、成功、失败、延迟、吞吐     |
+---------------------------------------------------------------+
| 操作结果或错误提示                                           |
+---------------------------------------------------------------+
```

当前工具栏提供浏览、加载、环境选择、场景选择、用户选择、开始/终止、暂停/继续、清空、导出和日志。XML 是唯一参数源；界面不提供新建、保存或参数编辑。修改 XML 后先终止当前压测，再点击“加载”从磁盘重新读取。

指标列表以保证列标题完整的宽度作为下限；可视区域宽于下限总和时，十列按比例占满全部宽度，不保留无标题空白区。日志列表固定保证“时间”和“级别”完整显示，剩余宽度全部分配给“消息”列。两类列表均在窗口尺寸变化后重新计算列宽。

## 4. 对话框和视图

### 4.1 `CMtLoadTestDlg`

- 持有 DLL 适配器、环境/场景/用户安全摘要副本、日志对象和指标列表。
- 只在 UI 线程创建和修改控件。
- 处理命令启用状态、定时刷新和退出确认。
- 不解析 XML/JSON，不计算压测指标。

### 4.2 `CMainDlg`

- 处理菜单命令和三个入口按钮。
- 每次只打开一个模态功能窗口，避免多个压力测试窗口竞争 DLL 和报告文件。
- 不保存任何压测、接口请求或数据文件状态。

### 4.3 `CInterfaceTestDlg`

- 提供环境、服务器、服务类型、报文协议、变量组、分类和接口选择。
- 字段表与原始 JSON 双向同步；必填字段不可关闭或删除，可选字段支持新增、编辑和删除。
- HTTP/HTTPS 请求及 WebSocket/WSS 接收在后台线程执行，通过窗口消息回到 UI 线程。
- HTTPS/WSS 使用配置指定的 PEM CA 校验证书链；官方 HP-Socket 6.0.9 不校验连接主机名，不得描述为严格站点身份认证。写操作发送前确认且不自动重试；CDN 入口证书链可能不同于源站证书，配置必须以实际访问入口为准。
- 接口测试顶部提供与其他功能键等尺寸的“日志”和“清空消息”按钮；日志窗口直接复用压力测试的 `CLogDlg`，保持展示与滚动行为一致。
- `/verify_password` 提取的 Token 只保存在内存会话中，不写回 XML。

### 4.4 `CReservedFeatureDlg`

- 当前仅由数据查看入口使用，只显示功能名称、边界说明和关闭按钮。
- 不创建后台线程，不读取配置，不建立连接，不打开或保存数据文件。

### 4.5 压测配置选择区

- 计划路径为只读显示，浏览只选择 XML 文件。
- “加载”每次调用 DLL 重新读取磁盘 XML 并执行完整语义校验。
- 环境下拉框来自 `Environments`，场景下拉框来自 `Scenarios`，用户下拉框来自 `Users`，均不修改 XML。
- 场景项显示中文名称、id、线程数、循环次数和计划总请求数。
- 用户项显示中文名称、id、MT 版本、节点和 Login，不显示 Password、Token 或扩展参数；选择具体用户会覆盖本轮场景 `UserRefs`，选择“按场景配置”则保持 XML 分配规则。
- 界面不实现计划树、属性页、账号表格或任何参数编辑器。

### 4.6 `CAggregateView`

使用虚拟列表或批量更新的 `CListCtrl` 展示 Label、样本、平均值、中位数、P90/P95/P99、最小/最大值、错误率、吞吐量及收发速率。

每次刷新按 RunId 和 SnapshotSequence 接受新快照；旧序号不得覆盖新数据。排序只作用于界面副本，不修改 DLL 快照。

### 4.7 `CTrendView`

- 绘制最近窗口的完成 RPS、P95、错误率和活动请求。
- 只保存降采样时间点，不保存每个请求。
- 默认每秒一点，显示窗口可配置，窗口外数据淘汰。
- 绘图数据来自连续快照差值，不重新计算累计百分位。

### 4.8 `CErrorView`

- 按错误分类、接口和时间筛选 DLL 返回的脱敏错误样本。
- 请求和响应摘要以只读文本显示。
- UI 再次屏蔽已知敏感列，但不承担核心脱敏责任。

### 4.9 `CLogDlg` 与 `CAppLog`

- `CAppLog` 只记录界面操作、DLL 状态变化、脱敏失败样本和终态接口汇总。
- 内存与日志列表均限制为 1000 条，避免长时间运行导致控件和进程内存无界增长。
- 日志按日期写入程序目录的 `log` 子目录，使用 UTF-8；清空显示不会删除磁盘记录。
- `CLogDlg` 参考 MtAssistant，提供时间、级别、消息、清空显示和打开日志文件。
- 不记录密码、完整 Token、请求正文、响应正文或逐条成功请求。

## 5. DLL 调用适配

`CLoadEngineClient` 是界面访问 DLL 的唯一入口：

- 启动时加载 `MtLoadEngine.dll`，查询 ABI 并解析所需函数地址。
- 包装句柄创建、配置加载、校验、启动、停止、快照和导出。
- 将 DLL UTF-8 字符串转换为 UTF-16 `CStringW`。
- 不改变结果码和统计值。
- 析构前停止刷新，等待所有 UI 后台调用结束，再销毁句柄和卸载 DLL。

动态库缺失、ABI 不兼容或导出缺失时，界面仍可打开配置，但禁用启动和导出，并显示明确错误。

## 6. 异步与消息

压测不使用 DLL 回调。DLL 内部异步运行，UI 使用定时器拉取状态和快照。

压测网络和调度在 DLL 内部异步执行；配置加载和导出是低频同步控制操作。接口测试使用自定义 `WM_APP` 消息接收后台 HTTP/HTTPS 完成结果和 WebSocket 状态/消息，关闭窗口时先取消网络操作再等待线程退出。

实际定时器：

| 定时器 | 周期 | 用途 |
| --- | ---: | --- |
| `CMtLoadTestDlg::kSnapshotTimer` | 1000 ms | 读取状态、指标和错误样本，刷新列表及状态栏 |
| `CLogDlg::kRefreshTimer` | 300 ms | 复制内存日志并追加到日志列表 |

定时器不执行文件导出、网络等待或 `MtLoad_Wait(INFINITE)`。

## 7. 运行控制

启动流程：浏览 XML -> 加载（LoadPlan + ValidatePlan）-> 选择环境、场景和用户 -> Start -> 定时刷新。任一步失败均保留 XML 文件并显示结构化错误。

停止流程：禁用重复终止 -> 调用非阻塞 Stop -> 定时查询 STOPPING -> 到达终态且已有样本后启用导出。

关闭窗口统一执行 Stop、Wait、Destroy 和 FreeLibrary；首版不支持关闭 UI 后继续压测。

## 8. 报告导出

界面只选择 XLSX 或 XML 格式并调用 `MtLoad_ExportConfiguredReport`。导出目录来自 XML `Reports.directory`，为空时使用 XML 同目录；文件名固定为 `LoadTest_yyyyMMdd_HHmmss.xlsx/xml`。

界面不得自行构造 XLSX/XML 或重新计算数据。导出成功后状态栏和日志显示 DLL 返回的实际路径；导出失败显示 DLL 结果码和错误文字。

## 9. DPI、尺寸和性能

- 支持系统 DPI 和每监视器 DPI，控件位置使用锚定或布局管理，不写死屏幕坐标。
- 主窗口设置合理最小尺寸，表格列支持保存用户宽度。
- 长错误摘要在日志窗口中使用可滚动列表查看。
- 每秒最多一次全量指标刷新；大量行使用虚拟列表或差异更新。
- UI 日志、趋势点和错误行均设置上限。

## 10. 本轮明确不做

- 不实现 TCP 传输、Binary 或 Protobuf 编解码；仅保留枚举、配置和适配器入口。
- 不计算平均值、百分位或吞吐量。
- 不直接链接 xlnt。
- 不实现 Worker、命名管道、远程 Agent 或多机控制。
- 不实现 symbols、K 线、双槽位的加载、编辑和另存；当前仅保留入口。
