# MtLoadTest 源码结构与模块说明

## 1. 当前状态

本文以 2026-10-12 当前源码为准。应用采用主入口对话框加独立功能窗口；压力测试与接口测试分别使用独立 XML。接口测试已实现 HTTP/HTTPS/Web JSON，数据查看仍为预留入口。

依赖方向固定为 `MFC 界面 -> 应用模型/传输接口 -> SocketClient -> HPSocket`。`InterfaceTestDlg` 不解析 XML/JSON、不实现底层网络请求；`interface_test` 模块不包含 MFC 对话框；压力测试只通过 `engine/LoadEngineClient` 访问引擎公共 ABI。工程根目录 `AGENTS.md` 固化这些规则，防止后续把业务与框架重新耦合。

## 3. 主窗口控件与行为

`IDR_MAIN_MENU` 包含 `ID_MENU_LOAD_TEST`、`ID_MENU_INTERFACE_TEST`、`ID_MENU_DATA_VIEWER`。三个菜单命令分别与 `IDC_OPEN_LOAD_TEST`、`IDC_OPEN_INTERFACE_TEST`、`IDC_OPEN_DATA_VIEWER` 按钮调用相同处理函数。`IDC_MAIN_STATUS` 只报告最近打开或关闭的功能窗口。

数据查看占位窗口继续使用 `IDC_RESERVED_TITLE`、`IDC_RESERVED_MESSAGE`。接口测试已经由 `CInterfaceTestDlg` 独立实现，不再复用占位窗口。

## 3.1 接口测试目录边界

- 接口测试源配置固定为 `MtLoadTest/conf/interface-test.xml`，压力测试源配置固定为 `MtLoadTest/conf/v3-http.xml`；构建后复制到对应输出目录的 `conf`。
- VS 项目将 XML 作为 `None` 项归入“配置文件”逻辑筛选器；“资源文件”仅包含 `.rc` 和图标。筛选器不改变磁盘目录，也不表示 XML 被编译进 EXE。
- `MtLoadEngine/conf` 不保存工具业务配置；接口测试和压力测试 XML 都由 `MtLoadTest/conf` 统一管理。
- `vender/tinyxml` 与 `vender/nlohmann` 由接口测试配置/JSON 层使用；网络层统一复用 `SocketClient` 及其 HPSocket 适配。
- TCP、Binary、Protobuf 只有枚举、矩阵和接口基类，没有伪实现。

日志窗口包含 `IDC_LOG_LIST`、`IDC_CLEAR_LOG` 和 `IDC_OPEN_LOG`。列表列为“时间、级别、消息”；清空操作只清除内存和当前显示，不删除已经落盘的记录；打开日志使用系统默认文本查看器。日志刷新前若最后一页可见，则在确有新记录时跟随到底部；用户已经向上滚动时不调用 `EnsureVisible`，保持当前阅读位置。

`CMtLoadTestDlg::kSnapshotTimer=1`，周期 1000 ms，只在 UI 线程调用状态、指标和错误样本查询。`CLogDlg::kRefreshTimer=1`，周期 300 ms，只复制本地内存日志。当前没有自定义 `WM_APP` 消息和后台任务。

## 5. DLL 所有权与关闭顺序

`CLoadEngineClient::Load` 在动态配置使用 `LoadLibraryW/GetProcAddress`，在静态配置直接绑定同名 C ABI；两者随后统一校验 `MTLOAD_ABI_VERSION`、初始化 Options 并创建句柄。关闭时由 `Unload` 顺序执行 Stop、无限 Wait、Destroy，动态版最后执行 FreeLibrary。

所有指标和错误样本分别由 DLL 复制到 `std::vector<MTLOAD_METRIC_ROW>`、`std::vector<MTLOAD_ERROR_SAMPLE>` 后再进入界面，界面不持有 DLL 内存。日志明确禁止记录密码、完整 Token、请求正文和响应正文。MFC 未包含 SocketClient、HPSocket、jsoncpp、TinyXML 或 xlnt 头文件。

账号、平台、节点和密码只存在于 XML `Users` 节点并由 DLL 解析。线程、循环、请求、请求头、正文和断言同样只存在于 XML。MFC 不提供账号表格或参数编辑器；它只读取 `MTLOAD_ENVIRONMENT`、`MTLOAD_SCENARIO` 和不含密码/Token/扩展参数的 `MTLOAD_USER` 摘要。

## 6. 计划文件

当前没有独立的 `RunController`、趋势图和错误筛选页；这些能力如后续落地，必须继续通过 `CLoadEngineClient` 读取 DLL 快照。计划树、属性编辑器和账号表格明确不在本工具范围内，不作为待实现项。

## 7. 源码注释约定

- 每个自有头文件必须说明模块边界；类、函数、枚举值、数据结构字段和成员变量均使用简体中文说明用途、生命周期或界面映射关系。
- 每个自有 `.cpp` 函数必须说明实现目的；涉及 MFC 消息、后台线程、SocketClient 生命周期、JSON 同步、敏感信息和关闭顺序时，必须补充关键步骤及失败路径。
- 注释不得把网络、配置解析或指标计算职责重新放回对话框；界面层、模型层、传输层和动态库适配层仍按本文依赖方向隔离。
- `vender` 中 TinyXML、nlohmann/json 和二进制依赖保持原样；`vender/MtLoadEngine/include` 是本工程随附的自有公共 ABI 副本，注释与动态库公共头同步。
