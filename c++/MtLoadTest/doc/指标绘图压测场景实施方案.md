# 指标绘图压测场景实施方案

## 1. 场景与工作负载分层

`conf/v3-http.xml` 是唯一业务计划。十个 Scenario 只描述请求步骤，十二个显式 Workload 负责测试类型和负载曲线；旧 Scenario.Load 仅用于 ABI 兼容。

- 查询场景：绘图查询、指标查询、配置查询。
- 生命周期场景：绘图、指标、配置分别执行新建、保存、查询、删除。
- 既有通用场景：登录查询、指定品种行情、全量行情和绘图批量同步。
- 界面下拉选择 Workload，不再为了冒烟、基准或耐久复制 Scenario。

## 2. 正式测试套件

- `chart-smoke`：1 用户、每个引用场景 1 个事务，覆盖三个查询和三个 CRUD 生命周期。
- 三个查询基准：closed 10 用户，每用户 100 次，分别得到单接口吞吐和延迟基线。
- 三个生命周期基准：closed 10 用户，每用户 10 次，每类 100 个事务、400 个请求。
- `chart-mixed-10m`：arrival 20 tx/s、10 分钟、最多 100 个执行用户；查询权重合计 80，写生命周期权重合计 20。
- `chart-soak-60m`：相同比例，arrival 10 tx/s、60 分钟。
- Stress、Spike、Breakpoint 提供阶段曲线示例，只允许人工选择，不作为默认自动运行项。

默认工作负载为 `chart-smoke`。第一批自动阈值只要求请求错误率为 0、丢弃事务为 0；真实环境另行核对删除后数据库无残留。延迟阈值必须取得稳定基线后再写入，不能预设生产 SLO。

## 3. 数据隔离和清理

- ID 使用 `loadtest-{类型}-${runId}-${threadIndex}-${iterationIndex}`，同一账号可被多个执行用户复用。
- 生命周期的删除步骤只携带本轮明确 ID，并设置 `alwaysRun=true`；禁止空 ID 或范围删除。
- 新建、保存、查询或删除任一步失败，完整业务事务均计为失败。
- `ChartSymbolId` 和 `ChartInterval` 由当前 User 参数提供；每个事务使用独立变量上下文。

## 4. 指标口径

- 接口列表显示请求 QPS、请求延迟、错误率和字节数，吞吐列名为“接口吞吐(全程 req/s)”。
- 业务事务列表单独显示启动、完成、成功、失败、丢弃、完整事务延迟和 tx/s。
- 生命周期中四个接口吞吐之和约等于事务吞吐的四倍；不能把四个 HTTP 请求当成四个业务事务。
- arrival 达到 `maxUsers` 后无法准时启动的事务记为丢弃，不等待、不补发。

## 5. 配置与发布

- Release 和 ReleaseStatic 构建均复制 `conf/v3-http.xml` 到各自运行目录。
- `MtLoadEngine/conf` 不保存指标绘图业务计划。
- 动态版 EXE 与 `MtLoadEngine.dll` 必须使用 ABI 4 同批产物；静态版链接同批 V4 静态库。

## 6. 验收

- 引擎解析结果为 10 个 Scenario，默认选择 `chart-smoke`，十二个显式 Workload 均可选择。
- Mock 验证权重轮询、阶段速率、暂停继续、最大用户、丢弃、阈值和报告。
- test 环境运行 10 分钟混合和 60 分钟耐久测试，核对两个 ClientData 均收到请求。
- 同时记录 MtLoadTest、Gateway 和两个 ClientData 的内存、线程、句柄、连接、错误和延迟趋势。
- 结束后使用数据库工具检查 `loadtest-` 测试数据无残留；未保存这些证据前不得宣称生产容量已验收。
