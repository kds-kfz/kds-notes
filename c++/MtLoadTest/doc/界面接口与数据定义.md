# MtLoadTest 界面接口与数据定义

## 1. 当前实现模型

当前界面不定义第二套压测状态或指标结构，直接复制 `MtLoadEngine` ABI 4 的 `MTLOAD_RUN_STATE`、`MTLOAD_METRIC_ROW`、`MTLOAD_SCENARIO_METRIC_ROW`、`MTLOAD_THRESHOLD_RESULT`、`MTLOAD_ERROR_SAMPLE`、`MTLOAD_ENVIRONMENT` 和 `MTLOAD_WORKLOAD`。这样可以确保 MFC 与 Runner 的工作负载选择、请求指标、事务指标、阈值及失败分类口径一致。界面不维护配置 DOM。

应用主窗口不接触上述结构，只用三个无参数命令打开对应窗口。接口测试由独立配置模型和传输接口实现；数据查看占位窗口只接收构造时复制的标题和说明字符串。

### 1.1 `CMainDlg` 入口函数

- `OnOpenLoadTest`：同步模态创建 `CMtLoadTestDlg`；返回后压力测试对象已经析构。
- `OnOpenInterfaceTest`：打开 `CInterfaceTestDlg`；读取 `MtLoadTest/conf/interface-test.xml`，不读取压测 XML。
- `OnOpenDataViewer`：打开数据查看占位窗口，不打开或修改任何文件。
- 三个函数均只允许 UI 线程调用，不阻塞网络或磁盘操作。

### 1.2 `CReservedFeatureDlg`

构造函数参数为资源模板 ID、窗口标题和说明文字，参数立即复制到 `CString`。`OnInitDialog` 设置标题、大小图标和两段静态文本；不返回业务错误码，不创建线程，不产生文件或网络副作用。

## 2. `CLoadEngineClient`

声明位置：`engine/LoadEngineClient.h`。类不可复制，拥有一个 `HMODULE` 和一个 `MTLOAD_HANDLE`。

### `Load`

- 参数：DLL 绝对 UTF-16 路径和中文错误输出。
- 行为：`LoadLibraryW` 后解析 UI 当前需要的导出，校验 ABI，调用 `MtLoad_InitOptions` 和 `MtLoad_Create`。
- 线程：当前只允许 UI 控制线程调用；会进行 DLL 文件加载但不发网络请求。
- 失败：释放部分模块，不留下句柄。

### `LoadAndValidatePlan`

- 参数：XML 绝对 UTF-16 路径；内部严格转换为 UTF-8。
- 行为：顺序调用 `MtLoad_LoadPlan`、`MtLoad_ValidatePlan`。
- 阻塞：同步读取 XML 内联数据或可选 CSV，当前由 UI 线程调用；大数据集后台化仍为后续任务。
- 失败：读取 DLL 最后错误，不在 UI 复制校验规则。

### `GetEnvironments` 与 `SelectEnvironment`

- `GetEnvironments` 通过公共 C ABI 复制 XML 中的环境列表，界面显示名称、id 以及 `scheme://host[:port]/basePath` 完整入口。
- `SelectEnvironment` 在启动前把下拉框选择提交给 DLL；运行中控件禁用，不允许改变请求去向。
- 环境数据不包含用户信息。用户列表通过独立 `GetUsers` 读取安全摘要，界面不解析 XML，也不接收 Password、Token 或扩展参数。
- `GetWorkloads` 返回 closed/arrival 模式、测试类型、场景数、用户范围、阶段数、持续时间和固定到达率；中文名称按 UTF-8 转为 UTF-16。
- `SelectWorkload` 传工作负载 id；场景权重、阶段曲线和阈值只由 DLL 解释。`GetScenarios/SelectScenario` 仍保留在 ABI 中供旧宿主兼容，当前界面不再以场景作为负载选择项。
- `GetUsers` 返回中文名称、用户编号、MT 版本、节点和 Login；`SelectUser` 传具体 id 覆盖本轮所有场景身份，传空字符串恢复按 UserRefs 分配。
- `ExportConfiguredReport` 只传 XLSX/XML 格式，目录和时间戳文件名由 DLL 按 XML 确定，返回实际输出路径。

### `Start`、`Stop`、`Pause`、`Resume`、`ClearResults`

- `Start` 调用异步 `MtLoad_Start`，成功只表示引擎接受运行。
- `Stop` 调用非阻塞 `MtLoad_Stop`，允许重复调用。
- `Pause` 停止新请求调度，`Resume` 从当前任务位置继续；界面不挂起操作系统线程。
- `ClearResults` 只在非活动状态清除指标和错误样本，不清计划与运行日志文件。
- 当前没有单独公开 `Wait` 控件；`Unload` 关闭时执行 Stop、无限 Wait、Destroy，确保模块卸载前线程已退出。

### `GetState`、指标、阈值、错误和 `LastError`

- `GetState` 初始化结构头并复制单个状态。
- `GetMetrics` 使用空缓冲区取得数量，再分配 `std::vector` 复制指标。
- `GetScenarioMetrics` 复制完整业务事务的启动、完成、成功、失败、丢弃、分位数和 tx/s，不混入接口列表。
- `GetThresholdResults` 在终态复制每条阈值的范围、指标、目标、比较符、期望、实际和通过状态。
- `GetErrorSamples` 使用相同的两次调用方式复制 DLL 内最多 1000 个失败样本；返回数组归 MFC 所有。
- `LastError` 使用字节数两次调用并转为 UTF-16。
- 返回容器由 MFC 进程拥有，不引用 DLL 内存。

## 3. 实际状态映射

界面直接显示 DLL 的英文状态名：`CREATED`、`PLAN_LOADED`、`VALIDATED`、`STARTING`、`RUNNING`、`PAUSING`、`PAUSED`、`STOPPING`、`COMPLETED`、`FAILED`。`UpdateControls` 统一决定按钮文字与可用状态，不另建第二套状态机。

## 4. 实际指标列

`IDC_TRANSACTION_LIST` 单独展示业务事务、启动、完成、成功、失败、丢弃、平均耗时、P50、P90、P95、P99 和事务吞吐。`IDC_METRIC_LIST` 展示：场景、步骤、接口、已请求/总请求、进度、成功、失败、平均耗时、中位数、P90、P95、P99、最小、最大、异常率、接口吞吐、接收 KB/s、发送 KB/s、请求大小和应答大小。字段直接来自 DLL：

- 文本从 UTF-8 转为 UTF-16。
- 计数按无符号 64 位格式显示。
- 平均、中位数、P90、P95、P99、最小值和最大值单位均为毫秒，保留两位小数；JMeter 的“95% 百分位”等同于现有 `p95Ms`，不重复计算。
- 异常率读取 `errorRate` 并转换为百分数，保留两位小数。
- 接口吞吐单位为完成请求/秒，事务吞吐单位为完整事务/秒，两者都使用扣除暂停后的全程有效运行时间，不能相互替代。
- 接收和发送速率分别读取 `receivedKiBPerSec`、`sentKiBPerSec`，以 1024 字节为 1 KB，保留两位小数。
- 请求大小读取 `sentBytes`，应答大小读取 `receivedBytes`，均为当前接口所有已完成网络尝试的累计业务报文字节数，不是单次平均值。
- 累计流量小于 1024 字节时显示 `B`；达到 1024 后以 1024 为进位逐级显示 `KB`、`MB`、`GB`、`TB`、`PB`、`EB`，统一保留两位小数，例如 `1126 B` 显示为 `1.10 KB`。
- 总请求读取 `plannedRequests`；持续时间和 arrival 模式为 0 时显示 `已请求/?` 和 `-`。
- 状态栏额外显示总请求吞吐、当前/峰值执行用户、当前/峰值在途请求、完成/调度事务和丢弃事务。

## 5. 控件和定时器

主窗口使用 `IDC_OPEN_LOAD_TEST`、`IDC_OPEN_INTERFACE_TEST`、`IDC_OPEN_DATA_VIEWER`、`IDC_MAIN_STATUS`。压力测试控件为 `IDC_PLAN_PATH`、`IDC_BROWSE_PLAN`、`IDC_VALIDATE_PLAN`、`IDC_ENVIRONMENT`、`IDC_SCENARIO`（界面标题为工作负载）、`IDC_USER`、`IDC_START_RUN`、`IDC_PAUSE_RUN`、`IDC_CLEAR_RESULTS`、`IDC_EXPORT_RESULTS`、`IDC_LOG_BUTTON`、`IDC_RUN_STATE`、`IDC_TRANSACTION_LIST`、`IDC_METRIC_LIST` 和 `IDC_STATUS_TEXT`。日志窗口使用 `IDC_LOG_LIST`、`IDC_CLEAR_LOG`、`IDC_OPEN_LOG`。

主窗口定时器 `kSnapshotTimer=1`，周期 1000 ms。`OnTimer` 同步复制状态、指标和错误样本；日志窗口定时器周期 300 ms，只复制本地日志。查询不允许在引擎函数中做网络操作。

## 6. 本地日志数据

`AppLogEntry` 只在 MFC 进程内使用：

- `sequence`：单调递增序号，用来防止定时刷新重复插入。
- `timestamp`：本地时间，格式为 `yyyy-MM-dd HH:mm:ss.fff`。
- `level`：`INFO`、`WARN`、`ERROR` 或 `DEBUG`。
- `message`：界面操作、状态变化、脱敏错误摘要或接口聚合结果。

日志写入 `<程序目录>\log\MtLoadTest_yyyyMMdd.log`，编码为 UTF-8、按 CRLF 分行。内存最多保留 1000 条；“清空显示”不删除日志文件。禁止把密码、完整 Token、请求正文或响应正文传入 `CAppLog::Add`。

`CMtLoadTestDlg::SanitizeDiagnostic` 在 DLL 错误文字进入日志前检查 `Token`、`Password`、`Passwd`、`Authorization` 和 `Secret` 等敏感字段名；命中时只写“详细值已隐藏”。这层保护不改变界面状态提示或 DLL 的核心脱敏责任。

## 7. 后续数据模型

`ST_UI_TREND_POINT`、错误筛选模型和自定义 `WM_APP` 任务消息仍为 `PLANNED`。参数编辑器不在本工具设计范围内；XML 始终是唯一配置源。

## 8. `CAppLog` 函数约定

### `Initialize`

- 输入：程序目录绝对 UTF-16 路径；错误信息由调用方持有。
- 行为：同步创建 `log` 子目录并探测当日日志文件是否可追加，不创建后台线程。
- 返回：成功返回 `true`；失败返回 `false` 并填写中文原因。失败后仍可使用内存日志。
- 线程：线程安全；程序生命周期只需调用一次。

### `Add`

- 输入：借用的日志级别和消息，函数立即复制；调用方不得传入密码、完整 Token 或报文正文。
- 行为：先把消息中的 CR/LF 归一为空格，再同步追加内存队列和 UTF-8 文件；内存超过 1000 条时淘汰最旧记录。
- 返回：无。磁盘失败不抛异常、不停止压测，记录仍保留在内存。
- 线程：由互斥锁保护；当前主要由 UI 线程调用。

### `Snapshot`、`FilePath`、`ClearMemory`

- `Snapshot` 返回完整副本，调用方拥有容器和字符串。
- `FilePath` 返回当前日志文件路径副本。
- `ClearMemory` 只清空内存，不截断或删除文件，便于保留定位证据。
- 三个函数均短时持锁，不执行网络操作。

## 9. `CLogDlg` 行为

- `RefreshRows` 每 300 ms 读取一次日志副本，按 `sequence` 只追加新行，列表最多显示 1000 行。
- `OnOpenLog` 调用系统默认文本查看器打开当前日志文件。
- `OnClearLog` 清空当前显示和内存副本，不删除磁盘文件。
- `OnClose`、`OnCancel` 只隐藏窗口；主窗口退出时才销毁对象。
- 日志窗口借用主窗口拥有的 `CAppLog`，不得晚于主窗口日志对象销毁。
## 10. 接口测试配置模型

- `TransportKind`：`Tcp`、`Http`、`Https`、`WebSocket`。
- `PayloadKind`：`Binary`、`Json`、`Protobuf`。
- `ServerProfile`：环境、逻辑服务组、scheme、host、可选端口、basePath、建连/请求超时、解压后响应正文上限 `maxResponseBytes`、TLS 和 Web 心跳设置。
- `InterfaceCase`：分类、中文名称、说明、方法、路径、风险、Header、Field 和 Extract。
- `FieldDefinition`：JSON Pointer、类型、必填、启用、敏感、值和中文说明。
- `SessionVariables`：变量组值、运行时 Token、敏感变量名和序号；运行时变量不写回 XML。

合法性矩阵集中在 `QueryTransportPayloadSupport`：HTTP/HTTPS 屏蔽 Binary；本版本只有 HTTP/HTTPS/Web 的 JSON 组合可发送，其余组合显示“待开发”。

## 11. 接口测试窗口消息

- `WM_APP + 301`：HTTP 后台请求完成，携带状态码、响应头、响应正文、耗时和收发正文大小。
- `WM_APP + 302`：WebSocket 收发消息，UI 追加时间、方向、FuncId、Topic、EventType、大小和摘要。
- `WM_APP + 303`：WebSocket 连接状态或错误；断线后不自动重连。

关闭窗口时先取消活动 HTTP 句柄，再关闭 WebSocket、停止心跳并等待后台线程退出。
