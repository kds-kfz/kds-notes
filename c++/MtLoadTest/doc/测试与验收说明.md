# MtLoadTest 测试与验收说明

## 指标绘图压测场景

- 加载 `conf/v3-http.xml` 后引擎应解析 10 个场景；界面选择的是工作负载，默认项为 `chart-smoke`。
- 三个生命周期场景的单循环请求数为 4，默认计划请求数均为 `10 * 10 * 4 = 400`；批量同步为 `10 * 10 * 2 = 200`。
- 同一账号被 10 个线程复用时，生成的业务 ID 必须包含不同的运行、线程和循环编号。
- 新建或保存失败时查询步骤不执行，但带 `alwaysRun=true` 的精确删除仍执行；不得发送空 ID 或全范围删除。
- MT4、MT5 真实联调分别核对新建、修改后的查询内容和删除后无残留；真实联调结果与自动 Mock 结果分开记录。

## 3. UI 线程验收

- 所有控件只从 UI 线程访问。
- `IDT_METRIC_REFRESH` 执行时间不应长期接近 1000 ms 周期。
- 每次定时刷新只读取 DLL 的复制快照，不发起网络请求。
- 运行期间窗口可拖动和缩放；导出只在终态可用。
- 正常刷新不在 UI 线程调用网络接口；窗口关闭允许同步 Wait，因为 Stop 会主动唤醒网络等待，目的是保证进程不残留。

## 4. 场景选择验收

- XML 可配置多个带中文名称的 Scenario 和 Workload；加载后下拉框显示显式工作负载及 ABI 兼容工作负载。
- 选择 Workload 后由 DLL 统一解释场景组合、事务权重和 closed/arrival 曲线；界面不自行调度。
- 加载成功后显示 XML 全部用户；选择具体用户后所有虚拟线程使用该用户字段，选择“按场景配置”后恢复 UserRefs。
- 用户列表和日志不得出现 Password、Token 或自定义敏感参数。
- 工作负载项展示模式、用户范围、阶段数、持续时间和场景数，状态栏及指标行与 DLL 一致。
- 修改 XML 前先终止当前运行，保存后点击加载，环境、场景和计划请求数必须刷新。
- 账号直接配置在 XML Users 节点；界面不提供账号表格、计划树或属性编辑，也不在日志展示密码。

## 5. 指标展示验收

- 表格列与 DLL 指标一一映射。
- 业务事务必须显示在独立列表；生命周期事务的四个接口样本不得被显示成四个事务。
- 压测完成后选中任意指标行并等待多个刷新周期，选中状态和滚动位置不得消失或跳动。
- JMeter 聚合列逐项映射 `averageMs`、`medianMs`、`p90Ms`、`p95Ms`、`p99Ms`、`minMs`、`maxMs`、`errorRate`、`throughputPerSec`、`receivedKiBPerSec` 和 `sentKiBPerSec`，界面不重新采样或估算。
- 请求大小等于 `sentBytes` 累计值，应答大小等于 `receivedBytes` 累计值；1023 B 显示为 `1023.00 B`，1024 B 显示为 `1.00 KB`，1126 B 显示为 `1.10 KB`，并覆盖 MB、GB 的进位边界。
- 总请求吞吐、当前/峰值用户、当前/峰值在途请求、调度/完成/丢弃事务来自 DLL，不由界面按 1 秒刷新推算峰值。
- 64 位大计数不截断，错误率和延迟格式正确。
- 按列排序不改变下一次快照的值。
- 旧 SnapshotSequence 不覆盖新快照。
- 趋势图只使用有界降采样点，长时间运行内存稳定。

## 6. DPI 与可用性

在 100%、150%、200% DPI 以及常用桌面分辨率验证：

- 路径、下拉框、控制按钮、列表和状态栏不重叠或截断关键命令。
- 长 Label、URL、错误摘要和中文内容可通过滚动或详情查看。
- 键盘焦点、Tab 顺序和默认按钮合理。
- 最小窗口尺寸下仍可停止正在运行的测试。

日志专项还需确认：窗口隐藏期间仍能接收新记录；再次打开不重复行；用户停留在底部时新增日志自动跟随，手动滚动到上方后等待多个刷新周期不得跳回底部；超过 1000 条只淘汰最旧显示；日志长文本可横向查看；“打开日志”使用当日实际文件。

## 7. 集成与一致性

使用同一 XML（默认 Users/UserRefs，Inline/CSV 仅兼容通用参数）在 MFC、Runner 和 Python 示例中分别运行本地 Mock 场景，比较：

- 最终状态和退出结果。
- 样本、成功、失败和错误分类。
- 平均值与百分位容许的显示舍入差异。
- JSON、CSV、XML、XLSX 报告内容；CSV 保持请求明细口径，JSON/XML/XLSX 同时包含事务和阈值。

MFC 显示值必须直接来自同一快照，不能因排序、筛选或趋势绘制改变报告结果。

## 8. 真实环境验收

先运行默认冒烟，再人工运行 10 分钟读写混合和 60 分钟耐久工作负载。核对两个 ClientData 的请求分流、错误率、延迟趋势、MtLoadTest/Gateway/ClientData 的内存、线程、句柄和连接趋势，并检查数据库中没有 `loadtest-` 残留。Stress、Spike 和 Breakpoint 示例不得自动运行。未取得服务端日志、报告和数据库证据前，不宣称真实 V3 容量验收完成。

## 10. 接口测试验收

- 配置路径必须为 `MtLoadTest/conf/interface-test.xml`；确认 `MtLoadEngine/conf` 没有接口测试配置。
- 开发环境 HTTP 显式端口 8086；测试环境 HTTPS 不配置端口并使用 443；Web 分别使用 ws/wss。
- HTTP/HTTPS 协议列表不出现 Binary；TCP/Binary/Protobuf 入口标注“待开发”并禁止发送。
- 校验字段新增、删除、可选开关、必填门禁，以及对象、嵌套对象、数组和根数组的 JSON Pointer 同步。
- 校验合法 HTTPS、过期证书、未知 CA、代理和连接失败提示；默认不得忽略 CA 链错误。官方 HP-Socket 6.0.9 不执行主机名匹配，域名不匹配不能作为当前客户端的通过项，需由受控 TLS 代理或补齐校验的自建库覆盖。
- 先调用 `/verify_password`，确认 `/Data/Token` 进入内存会话，后续 Header 和 Web 10001 能填充且界面/日志不泄露。
- 校验 Web 10001 首次绑定与 30 秒动态心跳、10002 订阅/退订/推送、10003 查询、10004 只读通知、5000 条淘汰和服务端断开。
- 关闭接口窗口和退出程序后，确认 HTTP 请求已取消、WebSocket/心跳线程已退出且无后台进程残留。
- 用 Mock 覆盖超时、取消、JSON/非 JSON 响应、响应大小上限、重复请求资源释放和写操作确认；真实 V3 联调覆盖 26+8 路由及健康检查。

- Release x64 与 ReleaseStatic x64 MFC 构建通过。
- 动态运行目录包含 `MtLoadTest.exe`、`MtLoadEngine.dll`、`libSocketClient.dll`、`HPSocket.dll` 和引擎所需 `xlnt.dll`；静态运行目录只保留 EXE、配置和 CRT/MFC 前置条件，不包含上述业务 DLL。
- `MtLoadTestTests` 与 `MtLoadTestTestsStatic` 使用同一回环用例通过；静态 EXE 导入表不包含 HPSocket、SocketClient、MtLoadEngine 或 xlnt DLL。
- 缺少依赖时显示明确错误，不静默退出。
- 文档、资源和源码通过 UTF-8/乱码检查。
- 最终发布包不包含真实账号 CSV、密码、Token 或测试报告中的敏感数据。
