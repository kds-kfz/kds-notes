# SocketServer 同进程多服务实例方案

审批号：`USER_PLAN_20260828_SOCKETSERVER_MULTI_INSTANCE_GATEWAY_STARTUP_FIX`

状态：`IMPLEMENTED`

## 背景与问题

当前 HTTP、WebSocket、TCP 工厂分别返回进程级单例，对应 HP-Socket 对象、Listener、回调、线程池、连接表、请求表、任务队列、序号和锁也保存在 `g_*` 全局变量中。同一进程第二次创建相同协议服务时会复用并覆盖第一套运行状态，无法可靠承载两个 HTTP 监听端口。

## 方案

- 服务实例使用“协议类型 + 逻辑服务名称”作为唯一键，逻辑名称默认 `"1"`。
- 保留旧无参工厂；新增 `CreateHttpSockInstanceByName`、`CreateWebSockInstanceByName` 和 `CreateTcpSockInstanceByName`。
- 每个实例独立拥有网络对象、Listener、回调、线程池、锁、连接和请求状态；数据热路径直接使用实例上下文指针，不按名称查表。
- 同类型同名称拒绝重复创建；同类型不同名称及不同类型同名称允许并存。
- 新增只读运行信息接口，暴露 ABI、协议类型、逻辑名称、内部实例编号、启动状态、绑定 IP 和端口。
- 进程级可变状态只保留线程安全工厂登记表；删除运行路径中的协议全局状态和跨实例生命周期锁。
- 日志必须携带协议类型、逻辑名称和内部实例编号；相同日志路径使用安全共享生命周期。

## 兼容边界

- 旧无参工厂继续创建名称为 `"1"` 的默认实例。
- 已有 `CSocketServer` 和 `CHttpAsynReq` 虚函数顺序不变。
- ABI 能力版本升级为 6；V3 必须使用同版本头文件、LIB 和 DLL。
- 不修改 HTTP、WebSocket、TCP 线协议和回调业务语义。

## 验收标准

- 同进程可同时运行两个 HTTP 和一个 WebSocket，三者回调、线程、队列和停机互不影响。
- 同类型同名称创建失败；同类型不同名称和不同类型同名称创建成功。
- 默认无参调用仍可工作，运行信息中的逻辑名称为 `"1"`。
- 单独停止任一实例不影响其他实例。
- 多实例并发测试、运行信息测试及 `Release|x64 /W4 /WX` 构建通过。

源码实现完成后状态更新为 `IMPLEMENTED`；运行压力验证完成后再登记运行验收结果。
