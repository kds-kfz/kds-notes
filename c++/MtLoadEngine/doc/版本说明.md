# MtLoadEngine 版本说明

## 1.0.0.27 - 2026-10-12

### HP-Socket 静态链接与双模式保留

- 保留既有 `Release|x64` 动态链；新增的静态调整仅作用于 `ReleaseStatic|x64`。
- HP-Socket 6.0.9 源码工程的 x64 Release 静态库改为 `/MD`，与 MFC、SocketClient、MtLoadEngine 和 xlnt 统一使用动态 CRT，避免 `LNK2038`。
- `SocketClient ReleaseStatic` 定义 `HPSOCKET_STATIC_LIB`；`MtLoadRunnerStatic` 链接 `vender/hpsocket/lib/x64vc14/static/HPSocket.lib`，不再复制或导入 `HPSocket.dll`。
- HP-Socket 静态归档已包含完整 zlib；SocketClient 静态配置不再重复编译自身 zlib 对象，动态配置仍保留原有内置 zlib 实现。
- 新增 `MtLoadEngineTestsStatic`，使用真实回环 HTTP、16 并发压力与完整生命周期验证静态网络链和资源释放。

### 验证结果

- 动态 `Release|x64`、静态 `ReleaseStatic|x64` 均构建通过；动态模式仍按原方式部署 `HPSocket.dll`。
- `MtLoadEngineTests` 与 `MtLoadEngineTestsStatic` 均输出 `MtLoadEngine ABI/lifecycle: PASS`。
- `MtLoadRunnerStatic.exe` 为 5,851,648 字节，PE 导入表不包含 `HPSocket.dll`、`libSocketClient.dll`、`MtLoadEngine.dll` 或 `xlnt.dll`。

## 1.0.0.26 - 2026-10-12

### HP-Socket 6.0.9 与压测稳定性适配

- 动态模式明确链接 `libSocketClient.lib`，静态模式改为链接 `libSocketClient_static.lib`；两个模式统一从 SocketClient 自有 vender 目录取得 HP-Socket 6.0.9，不再引用 SocketServer 的库目录。
- `MtLoadRunner` 静态配置同步采用相同链接边界：MtLoadEngine、SocketClient、xlnt、jsoncpp、TinyXML 静态链接，HP-Socket 继续使用官方 DLL。
- SocketClient 对同一 HTTP 连接增加单在途请求闸门，避免无请求 ID 的回调被重叠请求错误关联；连接失败、关闭、停止和响应完成均释放闸门。
- ABI/生命周期回归新增两轮 16 并发、每轮 320 次真实回环 HTTP 请求，校验全部样本成功、服务端请求数一致，且高并发预热后的第二轮不继续累计进程句柄。
- HTTPS 说明纠正为“CA 链校验”：官方 HP-Socket 6.0.9 设置 SNI 并验证证书链，但不校验连接主机名，不能描述为严格站点身份认证。

### 验证结果

- `Release|x64` 构建通过，ABI/生命周期测试通过。
- `ReleaseStatic|x64` 构建通过；静态运行器不依赖 `MtLoadEngine.dll` 或 `libSocketClient.dll`，仍按设计依赖 `HPSocket.dll`。

## 1.0.0.25 - 2026-10-10

### 静态 HTTPS 诊断与联调

- 为 `MtLoadRunner` 增加真正的 `ReleaseStatic|x64` 配置，直接链接 MtLoadEngine、SocketClient 和 xlnt 静态库，只保留 HPSocket 第三方动态依赖。
- SocketClient `Start` 失败时把 HPSocket 最近错误码送入传输回调，MtLoadEngine 在连接失败摘要中输出该错误码，避免仅记录无上下文的 `Connect` 失败。
- 使用静态运行器完成 test HTTPS CA 链校验联调，`POST /api/quotes` 返回成功并生成 1 个成功样本。

## 1.0.0.23 - 2026-10-09

### HTTPS 环境支持

- `Environment` 新增 `scheme=http|https`，省略时兼容旧计划并按 HTTP 处理。
- HTTP 默认端口为 80，HTTPS 默认端口为 443；显式 `port` 始终优先。
- 传输层按最终目标协议选择 SocketClient HTTP 或 HTTPS 客户端，HTTPS 使用 TLS 和证书校验，不自动跟随 3xx。
- `MTLOAD_ENVIRONMENT` 增加 `scheme`，公共 ABI 升级为 3，调用方必须整体更新头文件、LIB 和 DLL。

### 验证范围

- 增加环境 scheme 解析及 ABI 摘要回归；HTTP Mock 回归继续覆盖环境切换和请求路径。
- test 公网入口已确认 HTTP 会重定向到 HTTPS，配置改为 HTTPS 后直接访问 443。

## 1.0.0.24 - 2026-10-09

### HPSocket HTTPS CA 链校验

- 环境与目标增加 `tlsVerify`、`tlsCaFile`，HTTPS 在连接前通过 SocketClient 加载显式 PEM CA。
- 中文证书路径由标准文件系统读取，再以内存方式交给 HPSocket，避免其多字节文件接口无法打开中文路径。
- TLS 握手完成后才向执行层报告连接成功；握手关闭错误码进入失败摘要，便于区分证书失败和普通超时。
- 真实 `test.mhtradingterminal.com:443/api/quotes` CA 链校验联调通过：1 个样本、1 个成功、0 个失败；该版本不具备主机名匹配校验。

- 增加重复运行回归：第一轮只轮询到 `COMPLETED`、不调用 `Wait`，随后重新加载、校验、启动并确认第二轮 `runId=2`。

### 接口及数据变化

- 公共 C ABI、XML、CSV 及报告字段均未变化。
- `MtLoad_Wait` 语义不变；显式等待仍可提前回收 Worker。

### 影响范围

- 只修改 MtLoadEngine 的终态回收和重新加载行为，不修改 HTTP、变量、断言、调度和 MFC 展示逻辑。

### 验证结果

- `MtLoadEngineTests` Release x64 回归通过。
- `MtLoadEngine`、`MtLoadRunner` Release x64 构建通过。

## 1.0.0.18 - 2026-09-28

### 背景与问题

删除 gzip 请求头后再次压测仍收到约 10.41 KB 的压缩正文。复核正式 XML 发现该行被外部编辑缓冲重新写回，运行时实际仍发送 `Accept-Encoding: gzip`。

### 设计与实现

- 保持压测引擎不处理 gzip 的边界，不引入解压库和双重大小指标。

### 接口及数据变化

- 示例全局请求头增加 `Accept-Encoding: identity`；业务请求参数、C ABI、指标结构和报告格式不变。

### 影响范围

- 仅修改 `conf/v3-http.xml`、配置说明和版本说明，不需要升级 DLL 或 EXE。

### 验证结果

- 使用 `identity` 请求全量行情返回 HTTP 200，响应中没有 `Content-Encoding`，`Content-Length` 为约 81.5 KB。
- 同次实测请求正文 20 B、响应正文约 81,498 B，可直接执行 JSON 断言。

### 未完成与风险

- 若 XML 正在编辑器中打开，必须重新加载外部变更；用旧编辑缓冲再次保存会覆盖 `identity`。
