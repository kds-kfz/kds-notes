# MtLoadEngine 企业级接口压测设计

## 1. 设计目标

MtLoadEngine 将业务步骤、负载曲线和验收标准拆成三个独立层次：

- `Scenario` 描述接口步骤、变量、断言、提取和 `alwaysRun` 清理。
- `Workload` 引用一个或多个场景，定义 closed/arrival 负载和场景权重。
- `Threshold` 在运行结束后读取同一批指标，自动判断本轮是否达到验收条件。

同一个业务场景可复用于冒烟、基准、混合、压力、突增、拐点和耐久测试，避免复制步骤后产生配置漂移。

## 2. 执行模型

### 2.1 closed

- `users` 或兼容字段 `threads` 表示固定虚拟用户数。
- 每个用户顺序执行完整事务，支持 `iterations`、`durationMs` 和 `rampUpMs`。
- 多场景工作负载按稳定的整数权重周期选择场景；权重表示事务比例，不表示 HTTP 请求比例。
- 旧 `Scenario.Load` 只允许 closed。引擎为旧计划生成 `legacy-all` 和 `legacy-<scenarioId>` 隐式工作负载，旧 ABI 的 `SelectScenario` 继续有效。

### 2.2 arrival

- 调度器按 `ratePerSec` 产生业务事务到达事件，不等待上一事务完成。
- `preAllocatedUsers` 预建工作用户，繁忙时增长到 `maxUsers`。
- 达到 `maxUsers` 后不能准时启动的事务立即计入 `droppedIterations`，不进入隐藏等待队列。
- `Stage.durationMs` 定义阶段时长，目标速率在上一目标和 `targetRatePerSec` 之间线性变化。
- 初始速率和阶段目标允许为 0（用于停流或从 0 升载），负数及非有限值在计划校验阶段拒绝。
- 暂停时间不消耗阶段时长；恢复后继续按有效运行时间积分，不补发暂停期间流量。

## 3. 事务边界与失败处理

一次事务是一次完整 Scenario 迭代：

1. 普通步骤按 XML 顺序执行。
2. 同一步内的请求副本并行，步骤结束时统一提交提取变量。
3. `stop_iteration` 停止后续普通步骤，但 `alwaysRun=true` 清理步骤仍执行。
4. 任一普通或清理请求失败，事务均计为失败。
5. 只有到达事务终点才增加 `completedIterations`；停止打断的事务不伪装为完成。

运行时变量包含 `runId`、`threadIndex` 和 `iterationIndex`。每次迭代拥有独立变量上下文，场景混合时不会共享可变会话值。

## 4. 指标口径

请求指标 `MTLOAD_METRIC_ROW` 继续按“场景 + 步骤 + 请求”聚合：

- 样本、成功、失败、字节数和错误率。
- 平均、P50、P90、P95、P99、最小和最大请求耗时。
- `throughputPerSec` 是该接口完成样本数除以本轮有效运行时间。

事务指标 `MTLOAD_SCENARIO_METRIC_ROW` 单独统计：

- 启动、完成、成功、失败和丢弃事务数。
- 完整事务平均、P50、P90、P95、P99、最小和最大耗时。
- `throughputPerSec` 是完整事务完成数除以本轮有效运行时间。

`MTLOAD_RUN_STATE` 记录有效运行时间、总请求吞吐、当前/峰值用户、当前/峰值在途请求，以及已调度、已完成和丢弃事务数。总请求吞吐等于各接口全程吞吐之和；生命周期场景的事务吞吐不能与请求吞吐混用。

## 5. 阈值

阈值随 Workload 配置，支持：

- `run.errorRate`
- `run.throughputPerSec`
- `run.droppedIterations`
- `request.p95Ms`、`request.p99Ms`
- `scenario.p95Ms`、`scenario.errorRate`

比较符支持 `lte`、`gte` 和 `eq`。目标不存在按失败处理，避免拼写错误被解释成 0。阈值失败时运行状态仍为 `COMPLETED`，结果码为 `MTLOAD_E_THRESHOLD_FAILED`；阈值明细通过 ABI、JSON、XML、XLSX 和 Runner/MFC 日志输出。

## 6. ABI 与并发边界

- 公共 ABI 为 V4，动态 DLL、导入库、静态库、宿主头文件必须同批升级。
- 工作负载、事务指标和阈值结果均使用固定布局 POD 及两次调用协议，不跨 DLL 传递 STL 对象。
- 状态、指标和暂停计时分别由固定锁保护；请求、用户峰值和事务总数使用原子计数。
- arrival 工作池只排入已获得执行容量的事务，不使用无界队列掩盖被测系统变慢。
- 本版本仍为每请求建连；HTTP 连接复用、分布式发压和故障注入不在本次范围。

## 7. 配置示例

```xml
<Workloads default="smoke">
  <Workload id="smoke" name="冒烟" type="smoke">
    <Load mode="closed" users="1" iterations="1" />
    <ScenarioRef id="query" weight="1" />
    <Thresholds>
      <Threshold id="no-error" scope="run" metric="errorRate" operator="eq" value="0" />
    </Thresholds>
  </Workload>
  <Workload id="mixed" name="读写混合" type="average">
    <Load mode="arrival" ratePerSec="20" durationMs="600000"
          preAllocatedUsers="20" maxUsers="100" />
    <ScenarioRef id="query" weight="80" />
    <ScenarioRef id="lifecycle" weight="20" />
  </Workload>
</Workloads>
```

## 8. 验收边界

自动 Mock 覆盖 closed 兼容、权重、阶段升降、暂停继续、最大用户、丢弃、停止收敛、清理失败、阈值和报告。真实环境的 10 分钟混合测试、60 分钟耐久测试、两个 ClientData 分流、进程资源趋势和数据库无残留必须在部署环境单独留存证据，不能以本地 Mock 结果代替容量结论。
