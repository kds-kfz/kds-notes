# AGENTS.md

本文件约束 `MtLoadEngine` 可复用压测库的后续开发。工程同时提供动态库和静态库，不拥有 MFC 界面和工具配置。

## 工程边界

- `include` 只放对外 ABI、稳定数据结构和必要注释；`src` 放调度、HTTP 执行、场景运行、统计和内部实现。
- 压测库不得依赖 MFC 对话框、控件、资源文件或 `MtLoadTest` 源码，不得弹窗和直接操作 UI。
- 压测库不得读取、复制或修改 `MtLoadTest/conf`；计划内容由宿主读取后通过公开接口传入，或通过明确的库接口加载调用方指定路径。
- `MtLoadEngine/conf` 只允许存放压测库自身测试/示例所需内容，不得放接口测试或 MFC 工具配置。
- 业务场景模型、并发调度、HTTP 传输和统计聚合必须分层；协议传输层不得混入 MFC 展示字段和按钮状态。
- 公共 ABI 变更必须同步版本号、头文件、调用端兼容检查、测试和文档，不得静默改变结构布局或所有权语义。

## 并发与生命周期

- 线程数表示并发虚拟用户；每个用户独立执行所选场景及循环次数，用户之间不得共享可变请求上下文。
- 暂停只阻止领取新的步骤，已在途请求允许结束；继续从当前进度恢复；停止取消可取消操作并使下一次启动从头开始。
- 停机按“停止接单 -> 设置取消标记 -> 唤醒等待 -> 等待工作线程 -> 释放网络和同步对象”的顺序执行。
- 回调只传递不可变快照或明确所有权的深拷贝；不得在库锁内调用宿主回调。
- 所有线程、SocketClient 实例、事件和缓冲区必须有唯一所有者，并覆盖启动失败、取消、超时和正常完成路径。
- 网络客户端统一通过 `SocketClient` 适配 HPSocket；引擎内不得直接引入其他平台 HTTP API。
- `Release|x64` 必须链接 SocketClient 与 xlnt 的动态版本，`ReleaseStatic|x64` 必须链接它们的静态版本；禁止混合链接模式。
- 动态和静态产物必须共用同一 C ABI、同一实现源码和动态 CRT（`/MD`）；静态模式通过导出宏移除 `dllimport/dllexport`，不得复制实现。

## 配置、协议与统计

- XML 输入必须校验编码、根节点、ID 唯一性、交叉引用、范围和请求总数溢出；错误必须包含节点或字段位置。
- 请求字段按配置原样发送：存在且为空时发送空值；需要省略字段时删除配置，不在压测库内添加业务必填判断。
- 环境地址兼容域名/IP、可选端口和 basePath；未配置端口时 HTTP/HTTPS 分别使用 80/443。
- 统计口径必须明确：请求数、成功/失败、耗时分位、吞吐、发送/接收字节及速率均来自同一批已完成样本。
- 字节统计以实际提交的请求正文和实际接收的响应正文为基准；单位使用 1024 进制并保留两位小数。
- 新增协议通过独立 Transport/Codec 接口扩展，禁止在场景调度器中堆叠协议分支。

## 代码与注释

- 新增类、结构、关键函数、成员状态和复杂并发流程必须添加简体中文注释，说明职责、线程模型、所有权、失败路径和禁止事项。
- 注释解释设计原因和约束，避免复述代码。对外错误信息应具体且可定位。
- 类和函数遵守单一职责；重复逻辑超过 5 行时提取公共函数，长函数拆成有名称的阶段函数。
- 修改已有文件时保持原编码、换行和局部风格，不做无关格式化。
- 指针使用前判空，索引访问前检查范围，成员和内置局部变量必须初始化；禁止不安全 CRT 接口。

## 验证与文档

- 每次改动同步更新实现、公开头、示例配置、调用端适配、测试和文档。
- 至少覆盖配置校验、请求总数、并发隔离、暂停/继续、停止/重启、错误统计和关闭无残留线程。
- 完成后执行单元/Mock 测试、`Release|x64` 与 `ReleaseStatic|x64` 构建、最终导入表检查和 `git diff --check`。
- 新增、删除或移动源码时同步更新 `.vcxproj`、`.vcxproj.filters` 和 `docs/README.md`。
- 每批改动追加 `docs/版本说明.md`，记录问题、方案、影响、验证和未完成风险。
