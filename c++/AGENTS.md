# C++ 自研库与应用工程统一规则

本文件适用于本目录下全部自研 C++ 库、应用、测试和 Visual Studio 工程。工程目录中的 `AGENTS.md` 可增加更严格的专项规则，但不得降低本基线。

## 开发流程

- 修改前先阅读工程 README、版本说明和专题方案；接口、依赖或行为变化必须先更新方案。
- 所有库和应用的 `版本说明.md` 必须按时间正序维护：旧记录保持在前，新内容只允许追加到文件末尾；
  禁止在文件开头或历史记录之间插入新版本，也禁止覆盖、重排或改写既有版本记录。
- 源码、公共头、工程文件、测试和文档同步修改；新增或移动文件必须同步 `.vcxproj` 与 `.filters`。
- 保持原文件编码、换行和局部风格，不做无关格式化，不修改第三方源码来掩盖自研代码问题。

## 代码与命名

- 使用制表符缩进，大括号独立成行；`if`、`for`、`while` 即使只有一条语句也必须有大括号。
- 新代码的类、函数和变量使用工程既有命名体系：类 `C`、结构 `ST_`、枚举 `EN_`，参数 `p_`、成员 `m_`、全局 `g_`、静态全局 `s_`。
- 公共 ABI、历史协议字段和第三方符号不得仅为命名整改而改名；确需升级时提供版本化接口和迁移说明。
- 类和函数保持单一职责；重复逻辑超过 5 行应提取，核心逻辑原则上不超过 50 行。

## 注释与数据结构

- 注释统一使用简体中文，说明原因、约束、所有权和失败路径，不复述代码字面含义。
- 每个新增或修改的函数必须说明输入、输出、失败语义和线程安全要求。
- 每个新增或修改的数据结构字段、类成员必须说明用途、单位、有效范围、生命周期、所有权或关联配置。
- 非直观边界、长度取模、位运算、协议哨兵、兼容分支、并发状态切换和资源转移必须就地说明判断依据。
- 算法代码必须逐步说明数据变化；普通赋值、析构、花括号和明显判空不机械堆砌注释。

## 安全与并发

- 指针使用前判空，索引访问前检查范围；内置类型、指针和类成员必须初始化。
- 禁止不安全 CRT 接口；禁止日志输出私钥、密码、完整令牌、连接串和其他敏感数据。
- 线程、连接、句柄和缓冲区必须有唯一所有者；不得在持锁状态调用外部回调或执行阻塞 I/O。
- `DllMain` 不执行网络、线程、锁、文件 I/O 或复杂初始化。
- DLL 边界优先使用稳定 C ABI 或不透明句柄；由创建模块释放资源，禁止跨不兼容 CRT/编译器释放。

## VS2022 工程基线

- 新增 VS2022 x64 Release 工程默认使用 v143、C++17、`/MD`、Level4、SDL、符合模式和 UTF-8。
- 自研头文件按 Level4 治理；第三方头使用外部头告警隔离，不能全局关闭有价值告警。
- 同一产品的动态与静态构建共用源码、公共 ABI 和动态 CRT；静态库不得私自改用 `/MT`。
- 动态库加载使用应用目录或显式安全目录；发布清单记录版本、ABI、大小和 SHA-256。
- VS2010/VS2015 兼容工程保持原工具集和语言能力，只做可由该工具链验证的安全修复。

## 验证

- 每项实现改动都要有成功、边界和失败路径测试；并发或生命周期变更增加并发、取消和停机测试。
- 至少构建受影响的 Release 配置；提供动态/静态模式的库同时构建两种模式并检查最终导入表。
- 提交前运行相关测试、依赖/ABI 检查和 `git diff --check`，在版本说明记录命令、结果和剩余风险。
