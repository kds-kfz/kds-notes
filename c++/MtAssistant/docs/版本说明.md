## 2026-05-07 MtAssistant Breakpad 崩溃转储接入、nsdk 复用与工程属性整理

### 一、问题

1. Breakpad 静态库已经准备好，但工程 include 目录缺少第三方源码中的多级依赖头文件，构建时会继续出现头文件找不到的问题。
2. 测试崩溃 `*(int*)0 = 0;` 已能触发异常，但 `CrashDumps` 目录需要手动创建；目录不存在时 `ExceptionHandler` 不会自动生成 dump。
3. 原 `InitBreakpad()` 放在对话框初始化阶段，位置不是程序最早入口；如果主窗口创建前崩溃，可能捕获不到。
4. Breakpad 初始化代码散落在界面文件中，目录名 `CrashDumps` 直接硬编码，路径拼接和目录创建没有复用 nsdk。
5. `publicfunc` 中存在与 nsdk 重复的根路径、日期等工具函数，调用点不统一。
6. `#pragma warning(disable:4190)` 和 `#pragma comment(lib, "version.lib")` 写在源码里，第三方头警告和系统库依赖没有集中放到工程属性管理。

### 二、解决办法

1. 从 `F:\gwz\trank\breakpad\src` 提取 Breakpad 构建所需头文件，补齐到 `vender/breakpad/include`，并保留源码中的多级目录结构。
2. 补齐 `client/windows/common`、`client/windows/crash_generation`、`client/windows/handler`、`common`、`common/windows`、`google_breakpad/common` 等依赖头文件，解决 include 闭包缺失。
3. 在 `MtAssistant.vcxproj` 的 `Release|x64` 配置中加入 `vender/breakpad/include`、`vender/breakpad/lib/x64vc14`，并链接 `common.lib`、`crash_generation_client.lib`、`exception_handler.lib`。
4. 将 `InitBreakpad()` 移到 `public/publicfunc.cpp`，并在 `public/publicfunc.h` 中声明，保留原有初始化函数注释。
5. 在 `Service.cpp::CServiceApp::InitInstance()` 中尽早调用 `InitBreakpad()`，位置在主窗口创建之前，提升程序启动阶段崩溃的捕获概率。
6. `InitBreakpad()` 使用 `nsdk::GetRootPath()`、`nsdk::FolderExists()`、`nsdk::CreateFolder()` 和 `NSDK_PATH_DELIMETER`，目录不存在时自动创建。
7. 将 `CrashDumps` 提取为 `BREAKPAD_DUMP_FOLDER_NAME` 宏，避免目录名在代码中散落硬编码。
8. 更新 Breakpad dump 回调签名，补充 `MDRawAssertionInfo* assertion` 参数，匹配当前第三方库头文件。
9. 删除 `publicfunc` 中与 nsdk 重复的 `GetRootPath()`、`GetCurDate()`，相关调用点改用 nsdk 导出函数。
10. 移除源码中的 `#pragma warning(push/disable/pop)`，改由工程属性统一禁用 `4190` 警告。
11. 移除源码中的 `#pragma comment(lib, "version.lib")`，改为在工程链接器输入中配置 `version.lib`。

### 三、影响范围

1. 代码文件：`Service.cpp`、`ServiceDataMng.cpp`、`ServiceDlg.cpp`、`public/publicfunc.cpp`、`public/publicfunc.h`。
2. 工程文件：`MtAssistant.vcxproj`，主要涉及包含目录、库目录、附加依赖和禁用警告配置。
3. 第三方文件：新增 `vender/breakpad/include` 头文件目录树，使用 `vender/breakpad/lib/x64vc14` 下的 Breakpad 静态库。
4. 运行行为：程序启动后会更早注册 Breakpad 异常捕获；dump 默认写入程序根目录下的 `CrashDumps` 文件夹，目录不存在时自动创建。
5. 工具函数：根目录、日期、路径分隔符、目录判断和目录创建优先复用 nsdk，减少 `publicfunc` 中重复实现。

## 2026-05-06 MtAssistant 服务助手安全清理、停止流程增强与项目改名

### 一、问题

1. 工程中仍保留部分与行情业务相关的结构体、声明和功能性代码，当前服务助手并未使用这些能力，增加了维护边界和误改风险。
2. 服务配置读取缺少数量上限和严格校验，异常 `ini` 配置可能导致界面刷新、守护线程遍历和时间段处理压力异常。
3. 原停止流程主要依赖单个 PID 或窗口标题，遇到无标题控制台程序、父子进程、同名进程、多进程拉起或守护式重启时，可能无法完整停止目标服务。
4. 停止或重启服务时缺少明确的优雅退出窗口，服务没有足够时间释放文件、网络连接、日志和子进程资源；超时后的强杀与进程树清空确认也不够完整。
5. 频繁快速点击服务列表左侧勾选框时，列表状态变化、启停逻辑和状态刷新容易互相叠加；监控服务数量较多时，可能造成界面反应变慢甚至助手崩溃。
6. 部分中文日志、中文弹窗和界面提示不适合无中文语言包的国外运行环境，可能出现乱码或不可读提示。
7. 新增流程缺少统一中文注释规范，后续排查停止流程、守护线程和配置读取逻辑时不够直观。
8. 日志完整路径和“打开日志”按钮路径分别拼接，存在同一含义变量重复维护的问题，日期切换或路径规则调整时容易不一致。
9. 工程名称、解决方案、资源文件、配置文件和运行时展示名称仍混用 `HqAssistant` 与 `MtAssistant`，项目命名没有完全收口。

### 二、解决办法

1. 清理当前服务助手未使用的行情相关代码和功能性残留，保留服务助手需要的日志类、线程基类和硬编码交易终端能力；`public/Thread` 未做重写替代，基类继承使用视为有效使用。
2. 删除或移出当前工程不再使用的行情结构体、行情接口和旧全局变量相关文件，重点包括：
   `include/JztStructB.h`
   `include/KdscStruct.h`
   `include/Macro.h`
   `include/StructMF.h`
   `include/structB.h`
   `public/CrashDump.cpp`
   `public/CrashDump.h`
   `public/KdscInterface.h`
   `public/publicGlobalvar.cpp`
   `public/publicGlobalvar.h`
3. 配置读取增加安全边界：
   服务数量增加最大值限制；
   单服务重启时间段增加最大值限制；
   数量字段按 `int` 校验，负数按 `0` 处理，超过上限时截断并写日志；
   时间字段严格按 `HH:mm:ss` 解析，非法时间段跳过并写日志。
4. 保留交易终端固定窗口标题配置，用于停止流程补充定位目标进程；同时停止流程不再只依赖标题，避免无标题或标题变化导致无法停止。
5. 新增完整进程树停止能力 `StopProcessTree()`：
   通过已知 PID、进程名、完整路径和窗口标题综合定位根进程；
   基于系统进程快照向下收集所有子进程；
   每轮停止前重新扫描进程树，避免使用过期 PID；
   支持父子进程、多进程和守护进程短暂复活场景。
6. 停止流程按“先优雅，后强杀，再确认”执行：
   先向目标窗口发送 `WM_CLOSE`；
   对控制台进程发送 `CTRL_BREAK_EVENT`；
   最长等待 `5` 分钟让程序自行退出；
   超时后按子进程优先顺序强制结束；
   进程树清空后继续等待 `10` 秒确认，确认期间发现进程复活会再次强杀。
7. `StartProcess()` 创建服务进程时增加独立进程组，便于后续向控制台服务发送 `CTRL_BREAK_EVENT`，提升优雅停止成功率。
8. 守护线程新增可中断等待 `WaitForExit()`，将长时间 `Sleep` 拆成可被退出信号打断的分段等待，减少关闭助手或停止监控时的卡顿。
9. 服务列表勾选逻辑只处理 `LVIS_STATEIMAGEMASK` 状态位变化，过滤选中行、焦点变化等无关通知，避免快速点击触发重复启停逻辑。
10. 服务状态刷新改为 UI 线程定时器统一刷新，工作线程只维护服务状态和启停结果，避免跨线程直接操作列表控件导致崩溃风险。
11. 添加、删除、启用、停用服务时先落配置再更新内存状态，列表刷新时按配置数量和列表行数取较小值，避免删除服务后旧状态残留或越界刷新。
12. 将运行时中文弹窗、中文日志和界面文字调整为简短英文，例如无法激活窗口、强制退出确认、日志文件未就绪等提示，兼容国外无中文语言包环境。
13. 新增和调整的功能函数、变量、关键步骤统一补充中文注释，注释以 `wyl 2026-05-06：` 开头；涉及中文内容的源码按 GBK 安全读写，避免中文乱码。
14. 日志路径统一由 `CLog::m_strLogPath` 维护完整路径，并通过 `CLog::GetLogPath()` 对外暴露；“打开日志”按钮直接复用该完整路径，不再重复拼接日期日志文件名。
15. 工程整体从 `HqAssistant` 收口为 `MtAssistant`：
   解决方案改为 `MtAssistant.sln`；
   工程文件改为 `MtAssistant.vcxproj`、`MtAssistant.vcxproj.filters`、`MtAssistant.vcxproj.user`；
   资源文件改为 `MtAssistant.rc`、`res/MtAssistant.rc2`、`res/MtAssistant.ico`、`res/MtAssistant.png`；
   配置文件改为 `MtAssistant.ini`；
   About、窗口标题、日志弹窗标题、版本资源和注册表 Key 同步改为 `MtAssistant`。

## 2026-05-06 MtAssistant 已有服务接管、守护线程触发与状态显示优化

### 一、问题

1. 需要监控的服务如果已经在助手启动前运行，添加相同程序路径时，助手仍可能重新拉起一个新实例，导致同一路径服务重复运行。
2. 已存在服务被添加进助手后，配置中没有及时保存旧服务 PID，后续停止、重启和守护流程无法稳定接管原有进程。
3. 已存在服务添加后界面状态没有立即显示为 `Running`，容易误判为服务未启动。
4. 已存在服务虽然不需要重新启动，但后续勾选启用时仍应创建守护线程，并按界面配置的重启时间进行守护。
5. 添加或删除重启时间后，如果守护线程已经存在，需要同步最新时间配置，避免线程继续使用旧时间表。
6. 取消勾选只表示停止守护，不代表服务进程已经停止；原逻辑会把状态强制显示为 `Stopped`，和真实运行状态不一致。
7. 状态定时刷新存在未勾选兜底显示 `Stopped` 的逻辑，可能覆盖已有服务的真实状态显示。
8. 点击 `Browse` 打开系统文件选择框后，在当前运行环境中会触发 Shell 组件或扩展初始化相对路径日志，导致程序目录下创建同级 `log` 空目录。
9. 排查结论：同级 `log` 不是服务助手 `CLog::InitLog()` 创建；助手日志路径已统一为 `run\log`。只有调用系统/Shell 文件选择框时才复现，改为工程内目录枚举后不再复现，判断为当前环境中的 Shell 组件或扩展按相对路径初始化日志造成。

### 二、解决办法

1. 新增按完整路径查找进程能力：
   `FindProcessIdByPath()` 按进程名和完整程序路径精确匹配已运行服务，避免仅按窗口标题或旧 PID 判断。
2. 添加服务时优先检测同路径旧进程：
   如果检测到旧服务已运行，立即保存该 PID 到 `ServiceInfo` 和配置文件；
   界面状态列立即显示 `Running`；
   日志打印简短英文 `service already started`。
3. 守护线程启动前增加旧进程绑定流程：
   `BindExistingServiceProcess()` 会先按完整路径接管已存在服务；
   命中旧进程时写回配置中的 `Pid`；
   未命中时才允许后续 `StartProcess()` 拉起新服务。
4. `bat` 服务保留旧 PID 兜底：
   由于 `bat` 实际运行进程通常是 `cmd.exe`，无法稳定按脚本完整路径反查，仍通过旧 PID 判断是否存在。
5. 助手启动时只恢复已勾选启用服务的守护线程：
   未勾选服务即使已经运行，也只更新状态和 PID，不自动创建守护线程；
   勾选启用时才创建守护线程，符合当前界面操作语义。
6. 添加服务只保存配置和 PID，不创建守护线程：
   守护线程统一由服务列表左侧勾选触发；
   重复调用 `CreateDaemon()` 时只同步最新配置，不重复创建线程。
7. 时间配置变更继续同步到已有守护线程：
   添加或删除重启时间后，`UpdateTimeInfo()` 会刷新配置，并通过 `UpdateTimeDaemon()` 同步到当前守护线程。
8. 取消勾选时只销毁守护线程：
   不再将 `g_mapServiceStatus[iServiceRow]` 强制写为 `false`；
   不再立即把列表状态列改为 `Stopped`；
   当前服务状态显示保持不变，后续由真实进程探测结果刷新。
9. 状态定时器取消未勾选兜底停止显示：
   定时器只在拿到状态探测结果时更新状态列；
   没有状态结果时保留列表当前显示，避免取消勾选后错误显示停止。
10. 新增服务后立即更新 `g_iServiceCount`：
    确保 UI 定时刷新能覆盖刚添加的新行状态。
11. 相关新增函数、变量和关键步骤补充中文注释，统一使用 `wyl 2026-05-06：` 前缀；运行时日志继续保持简短英文。
12. `Browse` 文件选择流程去掉系统文件框，改为工程内自定义文件选择窗口；仅通过 `FindFirstFileA` 枚举本地目录和 `.exe/.bat` 文件，不加载 Shell 文件对话框组件，从根上避免点击按钮时创建程序同级 `log` 目录。
13. 旧的 `CFileDialog` 写法已保留在 `OnBnClickedLookButton()` 注释中，并补充中文说明；当前先试用工程内文件选择窗口，后续如需对比或回滚可直接查看该注释块。
