## 本次修改目标

本次修改目标是把 `CloudNetDataApi` 做成独立的业务网络库壳层，底层统一调用新版 `IceRPCPush`，上层服务插件只依赖 `CloudNetDataApi` 公共头和导入库，不暴露网络库实现源码，也不暴露 `IceRPCPush` 内部结构。

本次重点目标如下：

- 公共头只暴露 C API、句柄、结构体和回调函数类型
- 所有导出函数去掉 `CloudNetDataApi_` 前缀
- 封装同步 RPC、异步 RPC、同步 PUT、异步 PUT 和推送注册/注销
- 支持 Ice 服务端启动并通过回调处理远端请求
- 保持工程可直接使用 VS2022 `Release|x64` 构建

## 详细修改说明

### 1. 重写公共头为纯 C API

涉及文件：

- `project/vs2022/CloudNetDataApi.h`

本次修改内容：

- 公共头只保留 `extern "C"` 风格的 C 接口。
- 新增不透明句柄 `HCLOUD_NET_API`，调用方无法接触内部实现类。
- 新增公共结构体：
  - `ST_CLOUD_NET_BUFFER`
  - `ST_CLOUD_NET_RESULT`
  - `ST_CLOUD_NET_REQUEST`
- 新增回调类型：
  - `PFN_CLOUD_NET_REQUEST`
  - `PFN_CLOUD_NET_ASYNC`
  - `PFN_CLOUD_NET_PUSH`
- 结构体使用 `typedef struct ...` 形式，保证 C/C++ 调用方都能直接使用类型名。
- `StartService` 的压缩参数使用 `int p_iSnappyCompress`，避免公共 C 头依赖 C++ `bool`。

为什么这样修改：

- 服务插件只应看到稳定的 C ABI，不应包含 C++ 类、STL、IceRPCPush 内部类型或实现细节。
- `typedef struct` 和基础类型更适合跨编译器、跨语言边界调用。

预期效果：

- 业务和网络实现隔离
- 公共头更适合 DLL 调用方直接引用
- 后续服务插件不需要包含 `IceRPCPush.h`

涉及文件：

- `project/vs2022/CloudNetDataApi.def`
- `project/vs2022/CloudNetDataApi.h`
- `project/vs2022/CloudNetDataApi.cpp`

本次修改内容：

- 新增 `CloudNetDataApi.def`，只导出以下 14 个函数：

  - `StartService`

- DLL 内部编译时不使用 `__declspec(dllexport)` 额外导出 C++ 装饰名，统一由 `.def` 控制导出表。

为什么这样修改：

- 满足本项目公共 API 简洁调用要求。
- `.def` 是导出表的唯一权威来源，避免出现多余符号。

预期效果：

- 调用方只看到指定的 C API 名称

### 3. 实现 `CCloudNetDataApi` 内部封装层

涉及文件：

- `project/vs2022/CloudNetDataApi.cpp`

本次修改内容：

- 新增内部类 `CCloudNetDataApi`，只在实现文件中使用。
- 内部维护：
  - Ice 服务端句柄
  - 客户端连接表
  - 推送回调上下文
  - 异步调用上下文
  - 最近一次错误信息
- `Create/Destroy` 负责创建和释放内部对象。
- `Connect/Disconnect` 负责维护按连接名索引的 Ice 客户端连接。
- `GetLastError` 返回当前实例保存的最后错误信息。

为什么这样修改：

- 对外保持 C ABI，对内仍然可以使用 C++ 类管理资源和状态。
- 连接表、回调桥、错误信息都集中在一个内部对象中，调用方无需知道底层资源结构。

预期效果：

- 网络库实现不泄漏到服务插件源码
- 资源管理职责清晰
- 后续扩展连接池、续约、日志等能力更容易收敛到内部类

### 4. 封装 RPC/PUT 同步和异步调用

涉及文件：

- `project/vs2022/CloudNetDataApi.cpp`

本次修改内容：

- `CallSync` 封装 `JsonBinClientRPC`。
- `CallAsync` 封装 `JsonBinClientRPC_async`。
- `PutSync` 封装 `JsonBinClientPUT`。
- `PutAsync` 封装 `JsonBinClientPUT_async`。
- 同步返回结果统一深拷贝为 `ST_CLOUD_NET_RESULT`，调用方使用 `FreeResult` 释放。
- 异步回调内部先把 `IceRPCPush` 的结果深拷贝为 `ST_CLOUD_NET_RESULT`，调用用户回调后立即释放临时结果。
- 底层 `ST_JSON_M_RESULT_LEVEL` 始终在封装层内调用 `IJsonMutiResultFree` 释放。

为什么这样修改：

- 调用方不应管理 `IceRPCPush` 分配的内存。
- 深拷贝可以切断上层与底层结果对象生命周期的耦合。
- 同步和异步结果都使用同一套公共结果结构，减少插件侧适配成本。

预期效果：

- 内存所有权更明确
- 异步回调不会泄漏底层类型
- 上层业务调用同步/异步接口的方式统一

### 5. 封装服务端请求回调和推送注册

涉及文件：

- `project/vs2022/CloudNetDataApi.cpp`

本次修改内容：

- `StartService` 封装 `CreateJsonICEServer` 和 `RegServerCallBackFunc`。
- 服务端收到 RPC/PUT 请求后转换为 `ST_CLOUD_NET_REQUEST`，调用用户注册的 `PFN_CLOUD_NET_REQUEST`。
- 用户回调填充 `ST_CLOUD_NET_RESULT` 后，封装层回填到底层结果对象，并调用 `JsonICEResponseData` 完成回包。
- `RegisterPush` 和 `UnregisterPush` 封装 `RegisterJsonICEClient2`。
- 推送回调统一桥接为 `PFN_CLOUD_NET_PUSH`。

为什么这样修改：

- 服务插件只需要处理业务请求和返回业务结果，不需要接触 Ice AMD 回调对象。
- 回包必须复用 `IceRPCPush` 传入的内部结果对象，避免错误释放栈对象或普通对象。
- 推送注册和注销统一收口，便于后续插件实时注册逻辑扩展。

预期效果：

- 服务端请求处理链路简洁
- 避免底层回包对象生命周期错误
- 推送注册/注销调用统一走新版网络库

涉及文件：
- `src/CloudNetDataApi.cpp`

### 3. 生命周期和并发安全修复
