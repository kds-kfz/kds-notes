# AGENTS.md

本文件由 TradingTerminal V3 的工程规则裁剪而来，记录 CredCore 后续编码必须遵守的规则。已删除七服务、V2 迁移、Gateway 路由、IceGrid 和部署等与本密码认证库无关的条件。

## 适用范围

- 适用于 CredCore 的 C++ 源码、公共头文件、工程文件、测试和文档。
- 修改已有文件时保持原文件编码、换行和局部风格，不做无关格式化。
- CredCore 是安全边界库。修改密码算法、密钥材料、Token 格式、验签规则、返回码或依赖版本前，必须先完成兼容性和安全评审。

## 固定开发流程

1. 修改源码、公共头文件、工程或测试前，先阅读 `doc\README.md` 和 `doc\版本说明.md`。
2. 先在 `doc` 保存改造方案，说明背景、范围、接口、兼容性、风险和验收标准。
3. 按方案同步修改源码、公共头文件、工程、测试和文档，不得只改实现。
4. 每批实际改动追加到 `doc\版本说明.md`，只追加，不覆盖历史。
5. 收尾时分别记录源码完成、构建通过、自动测试通过和真实调用方联调状态。

## 版式规则

- 使用制表符缩进。
- 左右大括号独立成行，并与上一语句行首对齐。
- `if`、`while`、`for` 等流程控制语句即使只有一条语句，也必须使用大括号。
- 二元运算符前后加空格；分号、逗号前不加空格，后面加空格。
- 流程控制关键字与括号之间加空格，函数名和参数括号之间不加空格。

## 命名规则

- 变量名格式为“区域标识 + 类型标识 + 描述”，描述单词首字母大写。
- 函数名使用 PascalCase。
- 类名以 `C` 开头；结构体名以 `ST_` 开头；枚举名以 `EN_` 开头。
- `g_` 表示全局变量，`m_` 表示类成员，`p_` 表示函数参数，`s_` 表示静态全局变量。
- 常用类型标识：`i` 有符号整型、`u/n` 无符号整型、`l/ul` 长整型、`ch` 字符、`sz` 零结尾字符串、`str` 字符串对象、`p` 指针、`b` 逻辑型、`st` 结构变量、`cl` 类变量、`en` 枚举变量、`ref` 引用、`a` 数组。
- `std::size_t` 使用 `sz`，固定宽度整数在区域标识后保留位数，例如 `i64`、`u32`。
- 历史公开导出名 `Aes`、`Deaes` 和包含既有拼写 `Featrue` 的函数属于 ABI/协议，不得仅为命名整改而改名。
- OpenSSL、标准库和既有 AES 内核要求的外部类型或宏名称不受本工程命名规则约束。

## 注释规则

- 注释统一使用简体中文，禁止乱码。
- 注释解释用途、约束和原因，避免只重复代码字面含义。
- 算法函数必须做到数据流可逐步审计：每个移位、拼接、掩码、查表映射、摘要、签名、填充和密钥扩展步骤，都要在对应语句或连续表达式前说明输入如何变成输出以及采用该公式的原因。
- 长度取模、魔法边界、协议兼容哨兵、安全白名单、密码库返回值分类和资源所有权转移等非直观判断，必须在判断或操作前就地说明依据；查找表常量、花括号、普通返回、资源析构、普通空指针和容器判空不机械逐行堆砌注释。
- 每个新增或修改的函数必须说明输入、输出、返回值或异常、失败路径和线程安全要求。
- 每个结构体字段和类成员必须说明用途、有效期、所有权或关联配置。
- 默认构造函数必须初始化全部成员。
- 密钥、句柄、缓冲区、摘要和签名相关代码必须说明所有权、清理时机和敏感数据边界。
- 对外错误描述使用英文；源码注释和配置说明使用简体中文。

## 类和函数设计

- 类和函数遵守单一职责原则；单个函数核心逻辑原则上不超过 50 行。
- 生产函数物理跨度不得超过 300 行，Lambda 正文不得超过 20 行。
- 重复代码超过 5 行时应提取带中文契约注释的命名函数。
- 内部实现类型不得泄漏到公共 ABI；OpenSSL 类型只能出现在私有实现中。

## 参数、内存和安全

- 基础类型按值传递；非基础类型使用指针或引用；只读对象优先使用 `const` 引用。
- 指针使用前必须判空，除非同一函数内已经建立不可为空的不变量。
- 访问数组、`string`、`vector` 前必须保证索引不越界。
- 内置类型和指针局部变量定义时必须初始化；类成员必须由构造函数初始化。
- 禁止不安全的 CRT 函数，禁止把私钥、完整令牌或明文密码写入日志。
- 密码校验失败必须关闭放行，不能用异常或依赖错误降级为验证成功。
- 不得调用进程级 `OPENSSL_cleanup()`，不得破坏同进程其他 OpenSSL 使用方。

## ABI 与依赖

- 公共导出函数、返回码数值、Token 格式和历史错误语义未经审批不得改变。
- 公共头文件不得暴露 OpenSSL 类型；密码资源通过不透明句柄跨 DLL 边界传递，并由创建它的模块释放。
- 动态库和调用方必须使用兼容的 MSVC C++ ABI、平台、运行时和标准库边界。
- OpenSSL 和 nlohmann/json 版本必须与工程清单一致；更新版本时同步更新来源、哈希、构建参数和版本说明。

## README 与版本说明

- 新增、删除或移动 `.cpp`、`.h` 文件时，同步更新 `doc\README.md` 的代码结构和职责说明。
- 调整工程依赖、构建配置、输出产物或公开接口时，同步更新 `doc\README.md`。
- 每次改动在 `doc\版本说明.md` 追加背景、解决办法、影响范围、验证结果和剩余风险。

## 测试和提交

- 任何代码改动必须同步更新测试，至少覆盖成功、边界、失败和并发路径。
- 修改密码或编码逻辑时必须保留固定向量和兼容性测试，禁止只做随机往返测试。
- 动态库与静态库配置均需构建；生产使用形态必须运行兼容测试。
- 提交前逐行核对差异，避免无关改动，并记录实际执行的构建和测试命令。
