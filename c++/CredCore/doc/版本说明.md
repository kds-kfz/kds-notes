# CredCore 版本说明

## 2026-10-12 初始实现与本地未提交改动汇总

### 问题与边界

- 原 nsdk 同时承载通用系统能力和授权密钥、AES/Base64、Token 生成校验逻辑。
- V3 服务静态链接 nsdk 时，不使用授权功能的服务也会被动带入授权实现，因此将授权能力拆为独立库。

### 实现内容

- 新建 `CredCore` 工程，迁入 `Aes`、`Deaes`、`Base64Encode`、`Base64Decode`、
  `MakeFeatrue`、`BuildFeatrue`、`BuildFeatrueByPlainClientInfo`、
  `BuildFeatrueByPlainClientInfoSeconds`、`AuthFeatrue` 和 `AuthFeatrueByPlainClientInfo`。
- 公开接口位于 `credcore` 命名空间，并保留 `extern "C"` 导出边界；历史 `Featrue` 拼写、
  Token 格式、AES/Base64 算法和返回码保持兼容。
- `CredCore_define.h` 使用 `CRED_CORE_DEFINE_H` 保护宏，并提供统一命名空间宏。
- `Release|x64` 输出 `libCredCore.dll/lib/pdb`；`ReleaseStatic|x64` 作为可选形态输出
  `libCredCore_static.lib/pdb`，两种配置均使用动态 CRT `/MD`。
- V3 的 Gateway、Trade 使用动态 CredCore；其他服务不链接本库。
- 公司信息统一为 `Shenzhen Guangwz Technology Co., Ltd.`。

### 验证与风险

- 兼容测试覆盖 Base64、AES、自然日 Token、UTC 秒 Token、传统 Token 以及错误客户信息。
- 导出检查确认公开函数使用未修饰名称；但接口仍包含 `std::string`，调用方必须使用兼容的 MSVC C++ ABI 和 `/MD`。
- CredCore 是安全边界库，后续修改密钥、Token 明文结构或有效期规则必须独立兼容评审。

## 2026-10-20 RS256/JWK/JWT 公钥验签封装

### 实现内容

- 新增 `JwtRs256Verifier.cpp/.h` 私有实现和 5 个稳定导出接口，公共头文件只暴露不透明句柄，Gateway
  不需要包含 OpenSSL 头文件或链接 `libcrypto.lib`。
- 固定使用 OpenSSL 3.5.6、SHA-256 和 RSA PKCS#1 v1.5；JWK `n/e` 通过 Provider API 构造
  2048..4096 位只读公钥，并在运行时核对 OpenSSL 精确版本。
- JWT Header 使用 nlohmann/json 3.12.0 严格解析，只允许 `alg=RS256`；验签前后均不信任或解释
  Payload 业务声明。
- 新增独立 `EN_CREDCORE_RS256_RESULT` 返回码，覆盖格式、算法、`kid`、JWK、签名、OpenSSL 和依赖版本
  错误；历史 10 个接口、导出名、Token 格式和返回码保持不变。
- `Release|x64` 动态链接 `libcrypto-3-x64.dll`，不链接 `libssl`。`ReleaseStatic|x64` 可生成包含相同
  RS256 对象的归档，但 V3 生产仍只允许动态 CredCore。

### 验证

- DLL 与静态库均在 VS2022、x64、v143、C++17、`/MD`、`/W4 /WX` 下重新构建成功。
- 兼容测试保留原 AES/Base64/Token 用例，并新增真实 RS256 测试向量及算法、`kid`、签名、JWK 和
  Base64URL 负例；8 个线程共享同一不可变公钥句柄完成 800 次验签。
- `dumpbin` 确认旧 10 个导出未删除，新增 5 个未修饰导出；运行依赖只增加
  `libcrypto-3-x64.dll`。

## 2026-10-20 代码规范与 RS256 实现整改

### 背景与问题

- RS256 新实现和历史封装层存在结构体、字段、常量及局部变量未携带区域/类型前缀的问题，函数契约和
  AES 内核成员说明不完整。
- V3 的原始 `AGENTS.md` 同时包含七服务、V2 迁移、路由和部署条件，不能原样作为独立密码库规则。

### 解决办法与影响范围

- 新增 CredCore 项目级 `AGENTS.md`，保留通用 C++、命名、注释、内存、安全、ABI 和测试规则，删除与
  本库无关的服务条件；新增规范整改专题方案。
- RS256 私有结构统一为 `ST_` 命名，字段、文件常量、OpenSSL 资源别名和局部变量统一增加类型前缀；
  `CREDCORE_RS256_RESULT` 类型规范为 `EN_CREDCORE_RS256_RESULT`，枚举值和公开函数 ABI 不变。
- 为公开接口、私有辅助函数和 AES 内核补充简体中文契约，说明输入输出、失败路径、线程安全和资源所有权；
  AES 成员和固定表完成含义化命名，默认构造函数初始化全部字段。
- 增加“算法数据流可逐步审计”规则；为 Base64/Base64URL 的位拆分、移位、拼接、掩码和尾位约束，
  JWT 三段/Header、JWK 大整数、RSA 密钥与签名边界，以及 AES 填充和密钥扩展的特殊步骤补充就地依据说明。
- 修正 JOSE Header 解析参数为标准 JSON 严格模式，拒绝非标准 JSON 注释，避免与其他验签实现产生歧义。
- 删除 AES 内核未使用的错误文本和空链块变量；删除 JWK 解码成功后重复的空数组判断。格式、前导零、
  RSA 位数、指针和数组边界等安全校验继续保留。

### 验证结果

- `Release|x64` 和 `ReleaseStatic|x64` 在 VS2022、v143、C++17、`/W4 /WX` 下重新构建成功。
- 兼容测试通过，包含 Base64 固定向量、AES-CBC 固定密文向量、历史 Token、RS256 正负例和 8 线程
  共享句柄验签；新增无填充 Base64URL 长度余 1、非零残余位和 Header 注释三个固定负例。
- `dumpbin /EXPORTS` 仍为原有 15 个未修饰导出；`dumpbin /DEPENDENTS` 确认密码依赖仍只有
  `libcrypto-3-x64.dll`。
- 最终 `libCredCore.dll` SHA-256 为
  `C1CFD9C18AA2AFB106A5047A32838574BF4119288541F2678A1E4EF1A7E26ECA`。

### 未完成与风险

- AES/Rijndael 内核的数学控制流保持冻结，本次只做命名、注释、初始化和空指针防护，不替换算法实现。
- V3 实际 Gateway 联调不属于本次代码规范整改，仍需在服务集成阶段单独验收。

## 2026-10-22 1.0.0.3 稳定 C ABI 与导出白名单

### 背景与问题

- 历史 15 个接口虽然使用 `extern "C"` 固定了导出名，但参数或返回值仍包含 `std::string`，不同 CRT、
  编译器或标准库版本之间存在跨 DLL ABI 和内存所有权风险。
- DLL 仅依赖 `__declspec(dllexport)` 自动导出，缺少链接器级白名单；新增源码声明可能在未评审时扩大
  公共 ABI。
- 动态产物仍使用 `lib/x64vc14` 扁平输出，与当前自研库统一的 `dynamic/static` 目录规则不一致。

### 解决办法与影响范围

- 新增 `CredCoreC.h/.cpp`，使用 `ST_FACADE_STRING_VIEW`、`ST_FACADE_MUTABLE_BUFFER`、固定宽度整数和
  不透明句柄提供版本化 `CredCore_*` C ABI；调用方拥有输入和输出内存，容量不足时只返回所需长度，
  不写入部分结果。
- 新增 `CredCoreCxxAdapter.h` 作为调用方本地便利层；其中的 `std::string` 只在调用方模块内转换为字节
  视图，不再跨越 DLL 边界。
- 新增 `CredCore.def` 作为唯一导出白名单。旧 15 个 C++ ABI 导出暂留用于外部兼容，新调用方只能使用
  `CredCore_*`；V3 已全部迁移，不再导入旧符号。
- `CredCore_GetAbiInfo` 输出 ABI 版本、实现版本 `1.0.0.3`、OpenSSL `3.5.6` 和构建标识；ABI 版本不匹配
  返回 `FACADE_ABI_MISMATCH`，禁止静默降级。
- `Release|x64` 输出调整到 `lib/x64vc14/dynamic`，`ReleaseStatic|x64` 保持
  `lib/x64vc14/static`；两种配置继续使用 `/MD`，V3 仍只允许动态 CredCore。

### 验证结果

- DLL、静态库和兼容测试在 VS2022、x64、v143、C++17、`/W4 /WX` 下重新构建通过。
- 兼容测试同时覆盖原 15 项历史路径，以及 C ABI 信息、ABI 不匹配、输出容量不足不写半截数据、历史
  授权、JWT 指纹、JWK 公钥导入和 RS256 验签，输出 `CREDCORE_TESTS_PASSED`。
- `dumpbin /EXPORTS` 仅包含 `.def` 中的 23 个未修饰名称；V3 Gateway 只导入 6 个 `CredCore_*` 接口，
  Trade 只导入 1 个 `CredCore_*` 接口，Dynamic/Static 结果一致。
- `libCredCore.dll` 为 150,016 字节，版本 `1.0.0.3`，SHA-256 为
  `969D906749208B6752E4534A59B466F5D6F0DA6AA4FDFF78E4296E7DB5634857`。

### 未完成与风险

- 旧 15 个 `std::string` 导出仍是兼容面，不能用于新工程；删除它们需要独立主版本评审和全部外部调用方
  迁移证明，不能在 V3 本批次静默删除。
- 真实业务 JWT 声明校验仍由 Gateway 负责；CredCore 只验证密码原语，不解释 `iss/aud/login/instance_id`。
