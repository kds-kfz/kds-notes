# CredCore 代码规范与 RS256 实现整改方案

## 背景与问题

2026-10-20 新增的 RS256/JWK/JWT 私有实现已经具备验签能力，但部分内部结构体、字段、常量和局部变量没有遵守 V3 的“区域标识 + 类型标识 + 描述”规则，函数契约注释也不完整。历史 `CredCore.cpp` 封装层存在同类命名问题。继续在该基础上扩展证书、签发和认证能力，会增加所有权、线程安全和失败语义的理解成本。

CredCore 同时承担历史 Token 兼容职责。整改必须保持已发布 DLL 导出名、参数 ABI、错误码数值、AES/Base64 字节行为和 Token 格式不变，不能把代码规范整改变成协议重写。

## 改造范围

- 从 `mt5-terminal-v3\project\vs2022\AGENTS.md` 提取通用 C++、命名、注释、内存、安全、ABI 和测试规则，建立 CredCore 项目级 `AGENTS.md`。
- 删除原规则中七服务、V2 迁移、Gateway 路由、IceGrid、NATS、PostgreSQL 和部署等与 CredCore 无关的条件。
- 整改 `JwtRs256Verifier.h/.cpp` 的内部类型、字段、常量、别名和局部变量命名。
- 整改 `CredCore.cpp` 封装层的常量和局部变量命名，并补齐函数契约注释。
- 补齐 `CredCore.h` 公开函数的输入、输出、返回值、失败路径和线程安全说明。
- 整理 `aes.h` 的成员字段说明和接口契约；`aes.cpp` 作为既有兼容算法内核，仅做不改变控制流和密文字节的低风险命名与注释整改。
- 同步整改兼容测试命名，并补充能够约束本次安全边界的测试。

## 命名映射

- 私有公钥结构体改为 `ST_RS256_PUBLIC_KEY_VERIFIER`，字段使用 `strKeyId` 和 `pPublicKey`。
- Compact JWT 视图结构体改为 `ST_COMPACT_JWT_PARTS`，字段使用 `strHeader`、`strPayload`、`strSignature` 和 `strSigningInput`。
- 文件级常量使用 `s_` 区域前缀和类型前缀，例如 `s_szJwtHeaderMaxBytes`、`s_iRsaMinBits`。
- 局部变量按类型使用 `str`、`sz`、`i`、`u32`、`b`、`p`、`a`、`st`、`cl` 等前缀。
- `Aes`、`Deaes`、`MakeFeatrue`、`BuildFeatrue*`、`AuthFeatrue*` 是历史 ABI/协议名称，保持不变。

## 注释与数据结构要求

- 每个公开函数和私有辅助函数在声明或定义前说明输入、输出、返回/异常、失败路径和线程安全。
- 每个结构体字段和类成员说明用途、内存所有权、有效期和并发约束。
- OpenSSL 资源别名说明其释放函数；公钥句柄说明只读共享和销毁顺序。
- 算法函数按数据流逐步注释：移位、拼接、掩码、查表映射、摘要、签名、填充和密钥扩展的每个处理步骤，必须说明输入到输出的变换及公式依据。
- 对长度取模、容量估算、协议段数、控制字符、算法白名单、JWK 大整数、RSA 位数、签名长度、OpenSSL 返回值分类、兼容回退哨兵和 AES 填充等非直观判断，在判断前就地说明协议、数学或安全依据。
- 查找表常量、花括号、普通返回和资源析构不机械逐行注释；普通空指针、分配失败和容器判空继续由函数契约统一说明。
- 注释使用简体中文，不在日志或注释样例中记录真实令牌、私钥或客户数据。

## 冗余规则处理

“删除多余的条件”首先指项目规则裁剪：CredCore 的 `AGENTS.md` 不复制 V3 服务特有门禁。源码中的安全检查只有在能够证明被前置不变量完全覆盖、且不会改变错误码分类时才删除；JWT/JWK 长度、格式、算法、密钥位数、指针和数组边界检查不得以简化代码为由移除。

## 兼容性与风险

- 不修改公开函数签名和 DLL 导出名；返回码类型规范为 `EN_CREDCORE_RS256_RESULT`，各枚举值数值不变。
- JOSE Header 使用标准 JSON 严格解析并拒绝注释扩展，避免不同实现对签名 Header 产生歧义。
- 不修改固定测试向量、AES 密钥/IV、Base64 字节映射和 Token 明文布局。
- 不把 OpenSSL 类型暴露到 `CredCore.h`，不改变 OpenSSL 3.5.6 动态依赖边界。
- 内部类型和局部变量重命名不影响 ABI；AES 内核的改动必须通过全部固定向量和历史 Token 兼容测试。
- `std::string` 仍跨 DLL 边界，调用方必须继续使用兼容 MSVC C++ ABI 和 `/MD`。

## 验收标准

1. `Release|x64` 和 `ReleaseStatic|x64` 在 `/W4 /WX` 下构建成功。
2. 兼容测试覆盖 Base64、AES、三类历史 Token、RS256 固定签名向量、篡改、错误算法、错误 `kid`、非法 JWK/Base64URL 和并发共享句柄。
3. DLL 导出名和数量与整改前一致，运行依赖仍只新增 `libcrypto-3-x64.dll`。
4. 扫描新增 RS256 和封装层代码，不再出现无类型前缀的结构字段、成员或普通局部变量。
5. `doc\README.md` 和 `doc\版本说明.md` 记录实际完成范围和验证结果。
