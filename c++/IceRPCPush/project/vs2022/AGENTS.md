# AGENTS.md

本文件记录本工程后续编码需要遵守的规则。

## 适用范围

- 主要适用于本工程 C++ 源码、头文件、配置读取和接口业务实现。
- 修改已有文件时保持原文件编码、换行和局部风格，不做无关格式化和编码转换。
- 新增类、函数、成员变量、关键业务流程和复杂逻辑处，需要添加简体中文注释。

## 版式规则

- 使用制表符。
- 左右大括号独立成行，并与上一语句行首对齐。
- `if`、`while`、`for` 等流程控制语句即使只有一条语句，也必须使用大括号。
- 二元运算符前后加空格。
- 分号、逗号前不加空格，后面加空格。
- 流程控制关键字与后面的括号之间加空格，例如 `if (condition)`。
- 函数名和参数括号之间不加空格，例如 `DoWork(param)`。

## 注释规则

- 注释统一使用简体中文。切勿中文乱码。
- 文件注释、函数注释从行首开始书写。
- 重要功能块需要在块首语句前添加注释，并与代码对齐。
- 重要语句、运行时信息、错误码设置等需要添加说明性注释。
- 类成员变量建议添加注释，说明用途、生命周期或关联配置。
- 注释解释“为什么”和关键约束，避免只重复代码字面含义。
- 新增的关键函数、变量、类、数据结构都需要中文注释

## 命名规则

- 变量名格式：`区域标识 + 类型标识 + 变量描述单词...`。
- 函数名使用描述性单词组合，每个单词首字母大写。
- 类名以 `C` 开头，例如 `CTradeServerApp`。
- 结构名以 `ST_` 开头，单词全大写并用下划线分隔。
- 枚举名以 `EN_` 开头，单词全大写并用下划线分隔。
- 变量、函数、类名中的描述单词首字母大写。

常用区域标识：

- `g_`：全局变量。
- `m_`：类成员变量。
- `p_`：函数入参。
- `s_`：静态全局变量。

常用类型标识：

- `i`：有符号整型。
- `u` 或 `n`：无符号整型。
- `l` / `ul`：有符号/无符号长整型。
- `ch`：单字符。
- `sz`：以零字符结束的字符串。
- `str`：字符串对象。
- `p`：指针。
- `b`：逻辑型。
- `st`：结构变量。
- `cl`：类变量。
- `en`：枚举变量。
- `ref`：引用。
- `a`：数组。

## 类和函数设计

- 类应遵守单一职责原则，一个类尽量只有一个变化原因。
- 如果多个函数反复判断同一类条件分支，应考虑抽象基类和派生类，把公共流程放到基类，具体差异放到派生类。
- 函数应遵守单一职责原则，职责尽量拆小。
- 单个函数核心逻辑原则上不超过 50 行，不含变量声明和出入参设置。
- 不同函数中重复代码超过 5 行时，应抽取独立函数。
- 不同类中重复代码超过 5 行时，应考虑放到基类或公共接口类。

## 参数和数据传递

- 基础类型可以按值传递。
- 结构体、类对象等非基础类型应使用指针或引用传递。
- 不需要修改的对象参数优先使用 `const` 引用。
- 指针参数使用前必须判空，除非上下文已经明确保证非空。

## 配置读取

- 读取配置属性时必须做非法值判断。
- 没有读到配置值时应设置合理默认值。
- 新增配置属性需要在配置文件中添加注释说明。
- 文件路径长度应使用操作系统提供的最大路径宏或工程既有路径约束。

## 内存和安全

- 所有指针变量使用前必须判空，除非明确保证非空。
- 访问数组、`string`、`vector` 等元素前必须保证索引不越界。
- 类成员变量必须在构造函数中初始化。
- 内置类型和指针类型局部变量定义时必须初始化。
- 禁止使用不安全的 CRT 函数。
- 函数参数中的结构体和对象只能通过指针或引用传递。

## 提交和验证

- 提交前仔细核对每一行修改，避免无关改动。
- 提交前必须完成自测。
- 提测时说明测试要点。
- Bug 修复提交说明中应描述原因、修改方法和影响范围。
