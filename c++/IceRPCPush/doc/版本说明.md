说明：本节记录 `F:\开发资料\MyCode\kds-notes\c++\IceRPCPush` 今日迁移、依赖收敛、公共接口整理、编译告警优化和验证结果。编译中间目录、`.vs`、工程临时文件等不作为功能变更主体。

### 1. 公共入口文件和公共头文件收敛

修改前的问题：

- 旧版入口文件名和新版 DLL 工程入口命名不一致，容易出现 `JsoniRPC.cpp`、`IJsoniRPC.h` 与 `IceRPCPush.cpp`、`IceRPCPush.h` 双入口维护风险。
- 公共头中还残留 `ResponseData`、`JsonBinSrvGetClient` 两个旧声明，但旧版 `.def` 未导出、旧实现也不存在，Visual Studio 会提示缺实现。
- DLL 对外 ABI 需要继续以旧版 21 个导出函数为准。

本次修改内容：

- 将 DLL 对外公共入口统一到 `project\vs2022\IceRPCPush.cpp` 和 `project\vs2022\IceRPCPush.h`。
- 保留旧版 21 个导出函数名、函数签名和 `.def` 导出控制。
- 从 `IceRPCPush.h` 删除未实现、未导出的 `ResponseData` 和 `JsonBinSrvGetClient` 声明。
- `IceRPCPush.h` 继续作为 DLL 对外引用头，保留 `ICERPCPUSH_API` 导入声明；DLL 自身仍通过 `.def` 控制导出名，避免额外 C++ 装饰名导出。

预期效果：

- 外部调用方仍按旧导出函数链接。
- 新工程入口和公共头职责清晰，不再被旧文件名误导。
- Visual Studio 不再因为未实现声明产生无效提示。

### 2. SocketServer、nsdk 依赖收敛到本工程 vender

修改前的问题：

- 这会让 IceRPCPush 的构建依赖外部工程目录状态，移植或打包时容易漏文件。

本次修改内容：

- `project\vs2022\IceRPCPush.vcxproj` 的外部 include 路径改为：
  - `vender\SocketServer\include`
  - `vender\nsdk\include`
  - `vender\thread\include`
- 链接库路径确认使用：
  - `vender\SocketServer\lib\x64vc14`
  - `vender\nsdk\lib\x64vc14`
  - `vender\thread\lib\x64vc14`
- 保持链接库名不变：`libSocketServer.lib`、`libnsdk.lib`、`pthreadVC2.lib`。

预期效果：

- IceRPCPush 可以优先依赖本工程 `vender` 下的 SocketServer、nsdk、thread 库。
- 后续迁移、打包和版本归档时依赖来源更明确。

### 3. 第三方和旧 ABI 告警隔离

修改前的问题：

- Ice 3.8.2 头文件会产生大量 `C4251`、`C4275` 告警。
- nsdk 头文件会产生 `C4190` 历史告警。
- 旧协议结构体使用零长度数组，MSVC 会产生 `C4200`。
- tinyxml 静态库缺 PDB 会产生 `LNK4099`。
- 这些告警会淹没本工程真正需要处理的类型转换和格式串问题。

本次修改内容：

- 将 Ice、snappy、json、zlib、tinyxml、SocketServer、nsdk、thread 头目录通过 `/external:I` 作为外部头处理。
- 设置外部头告警级别为关闭。
- 在 `Release|x64` C/C++ 配置中禁用特定告警：
  - `4200`：旧 ABI 零长度数组。
  - `4251`、`4275`：Ice 头文件 DLL 接口类告警。
  - `4190`：nsdk 历史 C 链接返回 C++ 类型告警。
- 链接器增加 `/ignore:4099`，屏蔽 tinyxml 静态库缺 PDB 告警。
- 修正 `OutDir` 末尾斜杠，避免 `MSB8004`。

预期效果：

- 第三方和旧 ABI 噪音从错误列表中移除。
- 本工程真实告警可以被单独定位和修复。

### 4. 手写代码类型转换告警修复

修改前的问题：

- 多处 `size_t` 隐式赋值到 `int`、`long`，产生 `C4267`。
- `long long` 请求号隐式转换到 `DWORD`、`long`、`unsigned short`，产生 `C4244`。
- `SOCKET` 在 x64 下是指针宽度，传入 `int` 会产生截断风险。
- `HCLIENT` 指针句柄在日志中强转 `int`，x64 下会产生 `C4311`、`C4302`。

本次修改内容：

- 在 `src\publicfunc.h` 新增安全转换辅助：
  - `SafeSizeToLength<T>(...)`
  - `SafeLongLongToLength<T>(...)`
- `CompressAByte`、`UnCompressAByte`、RPC/PUT 回包、推送包、订阅包等长度字段统一使用安全转换。
- `Sendn(...)` 的 socket 参数由 `int` 改为 `SOCKET`，避免 x64 截断。
- UDP socket 相关成员改为 `SOCKET`，匹配 Winsock 类型。
- 订阅 map 查询前将 `p_lReqNo` 安全转换为 `DWORD`，避免 map key 隐式收窄。
- TCP 推送日志中的 `HCLIENT` 改为 `%p` 输出，不再转 `int`。

预期效果：

- 手写代码中的 `C4267`、`C4244`、`C4311`、`C4302` 告警清零。
- x64 平台下 socket 和句柄输出不再存在截断隐患。

### 5. 格式串和注释乱码清理

修改前的问题：

- 历史代码把日志系统自定义占位符 `%m_hSocket` 用在 `sprintf(...)` 中，MSVC 会产生 `C4476`、`C4474`。
- 注释中残留旧乱码文本，后续维护容易误判文件编码或业务含义。

本次修改内容：

- 将 `CJsonBinRPCImp.cpp` 中用于 `sprintf(...)` 的 `%m_hSocket` 改为标准 `%s`、`%p`。
- 相关 `sprintf(...)` 改为 `snprintf(...)`，并传入目标缓冲区长度。
- 日志类自身仍保留对 `%m_hSocket` 的兼容处理，不影响原日志调用。
- 清理 `JsonICEResponseData` 附近乱码注释，改成正常中文说明。
- 清理注释中的旧 `sprintf("%m_hSocket...")` 示例，避免扫描误报。

预期效果：

- `C4476`、`C4474` 告警清零。
- 源码中文注释不出现常见乱码标记。
