# TradingTerminal V3 版本说明

## 2026-08-05 Query `/bars` 保存侧流式归并补全

### 背景与问题

- 前一轮已经把 `/bars` 范围和尾部读取改为流式扫描，但后台保存和归档提交仍会读取完整 `.bars` 后构造合并数组；多年历史或并发归档时仍可能形成与文件大小相关的 Private Bytes 峰值。
- 正文损坏后若 `.coverage` 仍被保留，后续请求可能错误地把缺失历史判定为已覆盖。

### 解决办法

- 新增保存侧 `MergeWriteLocked` 分流：本次输入只在有界数组内归一化，旧历史不再整体载入内存。
- 顺序尾部使用约 1 MiB 固定缓冲流式复核旧正文校验和与顺序，追加正文并 Flush 后最后提交新 Header；提交失败恢复原文件长度和旧 Header。
- 重叠区间逐条归并到临时文件，验证旧文件校验和、记录顺序、容量和新 Header 后通过 `MoveFileExW` 原子替换。
- `.bars` 正文损坏时在同一文件锁内同步隔离 `.coverage`，后续请求重新执行 MT/Derive 恢复，不复用失效覆盖区间。

### 影响范围

- 修改 Query 私有历史存储与协议测试，并同步 Query/整体流程图、内存修复方案和第一阶段收尾计划；不修改 `1157`、28 个 HTTP URL、Web 协议、V2 `Code/Msg` 或公共 ABI。

### 验证结果

- 六服务 `TradingTerminal.sln Release|x64 /W4 /WX` 在最终代码上全量重建，结果为 `0` 警告、`0` 错误。
- 协议测试工程全量重建为 `0` 警告、`0` 错误，运行输出 `ALL_TESTS_PASSED`；用例覆盖 4096 根首次写入、顺序追加、重叠分钟按更高 `SourceEpoch/LastSequence` 修复、尾部读取和 bars/coverage 联动隔离。
- 本次命令、环境、静态检查和未完成项已归档到 `tests\reports\first-phase\20260805-204427-memory-boundary\summary.md`。

### 未完成与风险

- 尚未执行多年真实历史、慢磁盘、各写盘阶段断电注入、并发 `/bars`、V2 数据差分和 Private Bytes 两小时稳态测试；该改动仍不能作为生产内存验收结论。
- 当前状态保持“可联调、不可生产平替”。

## 2026-08-05 Quote、Trade、Query 内存增长边界修复

### 背景与问题

- 现场日志显示 Quote 在 Derive 持续拒绝时，未 ACK Tick 同时保存在 WAL 和进程内 `deqPending`，内存会随行情线性增长；约 12 分钟内出现 1309 次重试，MT4 ACK 长期停在序号 1。
- Trade 的旧发布包接收了约 24.3 万条非订阅通知并逐条写 `INFO`，公共日志队列又没有容量上限；现有多角色 MT Manager 连接还需要区分厂商 SDK 固定缓存和 V3 容器泄漏。
- Query 存在 PostgreSQL 已连接但状态仍为 `STOPPED`、历史文件全量读取、4096 个大对象保存任务以及永久增长文件锁映射等内存风险。
- 现场日志早于当前 EXE、XML 和 `libIceRPCPush.dll`，且采集后进程已经退出，因此只能确认代码层无界路径，不能直接给出真实稳态内存结论。

### 解决办法

- 公共日志改为 `65536` 条、`64 MiB` 双重有界并每 `100 ms` 刷新；满载时丢弃 `DEBUG/INFO` 并计数，`WARN/ERROR` 使用有界保留区。未知或拒绝通知只累计并每分钟输出一次脱敏摘要。
- Quote 删除全量未确认内存队列，改用最大 `64 MiB` 的分段 WAL、段号加偏移 ACK 和不超过 `batchTicks` 的当前重试批次；短写、轮换失败或 flush 失败会回滚本批新增段并保留原始错误，绝不报告成功或推进游标。
- Quote 为每个来源独立持有 `QUOTE_PUMPING` 和 `TIME_QUERY` 物理 API，周期校时不再断开、占用或锁住行情 Pumping 连接。
- Trade 增加 Dealer 终态保留和周期清理，默认保留 72 小时；只删除过期的已确认终态，`SUBMITTED/UNKNOWN` 永不自动清理或自动重试。
- Query 修正 PostgreSQL `STOPPED -> CONNECTING -> READY/SCHEMA_INVALID` 状态转换；历史保存队列限制为 256 个任务、262144 根 Bar 和 64 MiB，文件锁改为固定 256 分片，范围、尾部和校验改为流式文件处理。
- 内部 `1103 v2` 增加进程内存、线程、句柄、通知、日志队列及 Quote、Trade、Query 专项容量指标；保留 `1103 v1` 解码兼容，不改变外部 HTTP、Web、CloudNetDataApi 或 IceRPCPush ABI。

### 影响范围

- 修改公共日志与通知入口、Quote 分段 WAL 和 MT 连接隔离、Trade Dealer 状态、Query PostgreSQL/历史存储、内部诊断协议、dev/test XML、协议测试、启动手册及对应服务和整体流程图。
- 保留 V2 外部 `Code/Msg` 结构和错误描述；容量拒绝、历史池繁忙及下游拒绝均返回既有业务错误，不向前端暴露内部诊断字段。
- 未确认 Quote Tick 的数据主体改为磁盘所有，内存只拥有当前有界批次；该修改不改变 Tick 顺序、fencing、ACK、重放、M1 或 Profit 业务语义。

### 验证结果

- 六服务 `TradingTerminal.sln Release|x64 /W4 /WX` 已在最终源码上全量重建，结果为 `0` 警告、`0` 错误；六个 EXE/PDB 对均已更新到 `bin/x64vc14`。
- 协议测试覆盖 Quote 永久拒绝、有界批次、分段轮换、重启重放、ACK 压缩、轮换失败原子回滚和零段大小拒绝，以及 `1103 v1/v2`、Query 流式范围读取、256 锁分片、保存队列和 Dealer 终态清理；最终重建为 `0` 警告、`0` 错误，运行输出 `ALL_TESTS_PASSED`。
- 12 份 dev/test XML 已通过禁用 DTD 的严格解析；两个旧 GBK 源文件已无损转换为 UTF-8，活动文件按 `U+FFFD/U+951F/U+6D93/U+9359` 扫描并清理乱码。

### 未完成与风险

## 2026-08-04 V2 MT5 账户组有效报价完整接入 Derive/Query
