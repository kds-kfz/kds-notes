# TradingTerminal 内部协议登记表

## 1. 管理规则

- `TradingTerminalProtocol.h` 是六服务内部协议数值的唯一代码来源。
- `11xx` 只用于 Binary RPC/PUT，`12xx` 只用于 `Publish` 主动通知。
- 同步和异步调用共享同一个功能号，不因调用方式重复分配编号。
- 每段末位为 `0` 的编号只表示范围起点，不分配业务语义。
- 已发布编号只能标记为废弃，禁止重新分配给其他业务。
- 新协议必须先登记编号、目标服务、请求和应答结构版本，再编写分发代码和测试。
- 业务代码不得使用协议魔法数字，不得重新定义 `DC_PROTOCOL_*` 宏。

Query 当前仍保留“先缓冲 MtEventService `1211`，再逐节点调用 Quote `1122`”的旧冷启动代码；Quote 第一阶段已停止处理 `1122`，因此这是待迁移的端到端阻断项。目标链路由 Derive 提供最新行情和权威 M1 快照，Query 自己维护时间权威。`1211` 只更新最新行情，禁止在 Query 中生成 M1。`1157` 固定使用 V2 新模式，长期历史来自归档文件和 MT 历史池，重叠区由 SourceEpoch/LastSequence 更新的 Derive 双槽实时 M1 覆盖；没有新旧模式开关，也没有整请求直通 MT 的旧旁路。外部 `Offset` 只是兼容分页字段。Query 还后台消费完成日归档：dev 使用 `1187/1188`，test 使用实例唯一 durable 的 `MT_DERIVE_M1_ARCHIVE`。

30 个 V2 兼容 HTTP URL 的 `Code/Msg` 是外部稳定契约。命中 V2 已发布场景时必须返回原数值和原固定英文描述；内部 Binary 可以携带更详细诊断，但 Gateway 对外序列化时必须规范化。例如 `/bars` 的 `20000/20008/21022` 分别固定返回 `sys error, such as memory allocate failed`、`system not ready`、`mt manager connection busy`。V3 新错误码只能用于 V2 没有对应语义的场景。

#### 2.1.1 外部错误归一与上下文隔离

- 公共错误实现使用三张编译期只读有序结构体数组：V3 内部错误、V2 HTTP/Web/ClientData 兼容错误和 V2 网络关闭错误；查找使用二分算法，编译期断言和协议测试共同验证严格升序。
- `CodeMsg.h` 的全部错误枚举值和 V2 兼容别名必须逐项写简体中文触发条件；`CodeMsg.cpp` 的固定 `Msg` 必须保持已发布英文文本。新增错误码时两处必须同时登记，禁止只写英文枚举名或只补映射表。
- 30 个兼容 URL 在 Gateway 最终响应边界把具有 V2 等价语义的 V3 内部码归一为 V2 原 `Code`，再按最终 `Code` 输出固定 `Msg`；后端动态诊断只允许进入脱敏日志。
- Web `10001-10003` 的 JSON 和字段错误必须使用 `21000-21020` 精确码，不得统一返回 `40001`；成功固定为 `0/success`。
- `23000-23107` 的 V2 网络关闭错误与部分 V3 Trade/Derive Binary 错误数值重叠，必须按调用上下文分别查表，禁止仅按数字进行全局解释或对外透传。
- 未登记错误对外只返回 `unknown error`，不得拼接内部前缀、连接名、地址、账号或异常文本。真实 30 接口 V2/V3 错误差分仍是第一阶段生产阻断项。

### 2.2 MtTradeService 当前处理边界

- `1132-1142` 统一通过 Trade Binary 文档进入多 `Version+No` 节点路由，MT4 和 MT5 平台差异封装在 Adapter 内。
- 写请求可携带 `ClientRequestId`。相同键和相同请求摘要返回首次持久化结果；相同键但摘要不同返回 `TRADE_IDEMPOTENCY_KEY_CONFLICT`。
- 已提交到 MT 的操作与后续持久化状态分开表达。outbox 失败返回 `EventPersisted=false`，幂等结果失败返回 `IdempotencyPersisted=false`，都不能把已执行交易伪装为未执行。
- 成功项生成 `1221-1225` 或 `1241-1243` Reliable Event Binary 信封，使用 `Version+No+SourceEpoch+SourceSequence` 标识来源和顺序，并由 durable outbox 调用 `1172`。
- 敏感字段在生成事件前递归移除 Password、Passwd、MasterPasswd、InvestorPassword、Token、Certificate、PrivateKey 和 Secret。
- 每个节点按 `TRADE_COMMAND/TRADE_PRECHECK/STATE_PUMPING/CONFIG_PUMPING/PUMPING_QUERY` 建立互不借用的独立角色池，`count` 对应真实 SDK Adapter 数量；Pumping 连接由后台线程独占。真实 MT4/MT5 柜台语义、Dealer 最终状态和平台预检仍需部署环境联调。

### 2.3 MtEventService Reliable Event 当前处理边界

- Reliable Event 使用独立 Binary domain `4`，Query、Trade、ClientData 与 Reliable 文档禁止跨领域解码。
- `1172` 使用 `Nats-Msg-Id=EventId` 发布；JetStream 去重命中时不重复触发在线 `122x/124x` 通知。
- `1173` 为每个消费者创建独立 durable pull consumer，返回事件正文和进程内 AckToken；不向调用方暴露 NATS reply subject 或消息句柄。
- `1174` 使用 `natsMsg_AckSync` 显式确认。批量 ACK 部分成功时返回已确认数量和首个失败令牌，已确认消息不会回滚。
- `1175` 返回 Stream 和可选 Consumer 状态。未 ACK 消息在 AckWait 到期或 MtEventService 停止释放本地句柄后由 JetStream 重投。
- 当前实现覆盖追加、拉取、ACK、状态查询和 Derive 本地 DLQ。`MtDeriveDlqTool` 可查看、导出并按 EventId 提交受审计重放；三节点 MaxDeliver、容量、分区和长期 checkpoint 仍需 test 实测。

### 2.4 MtDeriveService 当前处理边界

- `1182` 的 Derive 兼容处理代码仍保留，但 Quote 第一阶段不再生产该请求；Derive 后续改为消费 Event `1211`，并在 Epoch 旋转或 Sequence 缺口时通过 Query `1168` 补齐当天 M1。
- Quote 不持有 WAL、ACK 水位或派生检查点。消费者不得把 `1211` Best Effort 在线流当作可重放日志，断线和重启恢复由各业务 Owner 自行负责。
- `1185` 返回稳定排序的 M1 快照；请求正文原保留位现定义为 `OpenPriceOnly=0/1`，为 `1` 时忽略普通范围遍历，只返回有确认值的品种且每品种最多一根最近确认交易日首 M1。`1252` 使用同一应答契约承载单条或小批最终 M1 状态，经 MtEventService 校验来源后中继给 MtQueryService。
- `1183` 使用 Gateway 实例、启动代次、递增 Revision 和租约时间管理绝对 Login 集合；陈旧 Revision 不得覆盖新需求。
- `1184` 的协议、Gateway 调用和 Profit worker 已落地。Derive 通过 `1173/1174 + 1167` 恢复账户、持仓、品种、组和汇率状态；来源未恢复完整时继续返回 `DERIVE_STATE_BOOTSTRAPPING`，禁止返回模拟或默认零收益。
- `1186` 返回 Tick 来源水位、WAL、有效租约及派生状态，并以可选尾部诊断块返回映射文件、spool、最老任务、归档水位、消费者 ACK 和回填数量；新 Decoder 仍接受旧版无扩展正文。
- Derive 每 60 秒将当前 Broker 日通过 `1168` 校准到稳定水位，并在完整历史日确认后原子写 spool。晚到 Tick 重新打开历史槽并以更高 FileGeneration 生成修复 ArchiveId。
- `1187/1188` 只用于 dev 单实例拉取；test 使用三副本 `MT_DERIVE_M1_ARCHIVE`，Query 在全部周期与 coverage 成功持久化后才 ACK。`1252` 只承担实时 M1 通知，不能替代可靠归档。
- `dev` 可关闭可靠消费，`test` 必须启用并在三节点 JetStream、归档 Stream 或权威依赖不可用时启动失败；真实 JetStream 和权威 MT 状态仍需外部联调。
- DLQ 重放不重新调用 `1172`，避免相同 `Nats-Msg-Id` 被 JetStream 去重窗口静默抑制；Derive 从实例独占收件箱读取完整信封，默认按 Query 快照水位和实体 `SourceSequence` 拒绝状态回退，显式越过保护必须进入审计。

### 2.5 `1103` v2 内存与容量诊断

- `1103` 响应版本 2 在 v1 的实例和租约公共前缀后追加可选指标；v2 Decoder 必须继续接受 v1 正文，v1 Decoder 只消费其已知公共前缀。
- 公共进程指标包括 Private Bytes、Working Set、Peak Working Set、线程数和句柄数；公共队列指标包括日志队列条数/字节、各级丢弃数、通知接收/拒绝/未处理数。
- Quote 通过 `1124` 按 `Version+No` 返回连接状态、SourceEpoch、Sequence、队列深度、最近 Tick、重连、淘汰和发布失败计数，不返回连接凭据。
- Query 返回历史保存队列任务数、Bar 数、字节数、固定锁分片数和 PostgreSQL 状态；Trade 返回五类角色连接数、重连次数、Dealer 各状态数量和 outbox 积压。
- 所有指标只用于内部监控和验收，不得混入 V2 HTTP 响应；禁止返回地址、账号、密码、Token、完整账户数据或文件正文。

### 3.1 `1211` 行情两跳语义

`1211` 使用两次 Publish，禁止 MtGatewayService 直接订阅 MtQuoteService：

1. MtQuoteService 发布到 MtEventService：外层 `SourcePlugin=MtQuoteService`，`Sequence/TimestampMs` 等于本条 Quote 的入口序号和入口时间。
2. MtEventService 发布到 MtGatewayService：外层 `SourcePlugin=MtEventService`，使用 Event 实例自己的中继序号和中继时间。
3. 原始 `Version+No+SourceEpoch+Sequence` 始终保存在 ClientData 和 Quote Tick Binary v1 正文，消费者据此做订阅过滤、同源顺序判断和缺口恢复。
4. Event 外层中继序号只用于事件中心发布关联，不得覆盖或冒充行情源序号。

MtEventService 的订阅字符串固定包含 `|1211`。该通知模式固定为 `BEST_EFFORT+UPDATED`，队列满时淘汰最旧 Tick，不提供 ACK、Replay 和历史补发。

### 3.2 Quote Tick Binary v1 布局

Quote Tick Binary 使用小端序。内部协议尚未发布，当前只接受 v1、固定头长 `108` 字节；旧开发态 v3-v6 不迁移、不兼容读取。MT4/MT5 由独立的 `PlatformVersion=4/5` 表示，不能占用协议版本：

| 偏移 | 长度 | 字段 | 约束 |
| ---: | ---: | --- | --- |
| `0` | 4 | `Magic` | `0x5451544D`，字节文本为 `MTQT` |
| `4` | 2 | `ProtocolVersion` | 固定为 `1` |
| `6` | 2 | `HeaderSize` | 固定为 `108` |
| `8` | 2 | `PlatformVersion` | 只允许 `4` 或 `5` |
| `10` | 2 | `Reserved` | 必须为 `0` |
| `12` | 4 | `SourceNo` | 有符号 32 位正整数 |
| `16` | 8 | `SourceEpoch` | Quote 来源启动代次，非 `0`，进程启动和原连接恢复后旋转，不承诺跨进程持久化 |
| `24` | 8 | `Sequence` | 当前 SourceEpoch 内严格递增且非 `0` |
| `32` | 4 | `SymbolLen` | `1-64` 字节 |
| `36` | 8 | `Flags` | MT SDK 原始 Tick 标志；MT4 为 `0` |
| `44` | 8 | `ServerTime` | MT SDK 原始服务器秒时间，不执行 UTC 转换 |
| `52` | 8 | `ServerTimeMsc` | MT SDK 原始服务器毫秒时间；整秒部分必须与 `ServerTime` 一致 |
| `60` | 8 | `IngressTimeMs` | Quote 收到 Tick 的 Unix 毫秒时间 |
| `68` | 24 | `Bid/Ask/Last` | 三个 IEEE 754 double；Bid/Ask 为有限正数，Last 可为 `0` |
| `92` | 16 | `Volume/VolumeExt` | SDK 原始成交量和 MT5 扩展精度成交量 |
| `108` | `SymbolLen` | `Symbol` | 合法 UTF-8，不允许 NUL、控制字符或尾随字节 |

Quote Tick Binary v1 作为 `EN_PLUGIN_BINARY_VALUE_BYTES` 放入 ClientData Binary。ClientData 的 `Topic/Version/No/Symbol/Sequence/TimestampMs` 必须和 Quote 正文字段完全一致；通知元数据还必须是 Quote 来源、`BEST_EFFORT+UPDATED`，且 Sequence/Timestamp/PayloadLen 与 ClientData 一致。任一层不一致时 MtEventService 在入队前拒绝。

Quote 第一阶段忽略 MT5 `OnTickStat`，不写入 Open/Close/Low/High/PrevClosed，不提供 `1122` 快照。MT4 OpenPrice、行情快照、M1、归档和历史补齐都由 Derive/Query 后续协作完成；在这些消费者迁移完成前，不得声称六服务行情链路已经通过端到端验收。

## 4. Web 隔离

Web 功能号只定义在 MtGatewayService 的 `MtGatewayWebProtocol.h`：

| 编号 | 用途 |
| ---: | --- |
| `10001` | 心跳 |
| `10002` | 订阅、退订和业务推送 |
| `10003` | 订阅状态查询 |
| `10004` | 交易源重同步通知 |

MtGatewayService 将 Tick、订单、成交、持仓、保证金、配置、收益和 K线通知转换为 `10002`；将交易源状态转换为 `10004`。其他五个服务不得包含或解析 Web 功能号。

`10002` 的 Topic 位为：Quote=`1`、Symbol=`2`、Profit=`4`、Order=`8`、Position=`16`、Deal=`32`、User=`64`、Kline=`128`，完整掩码为 `255`。Kline 初始快照来自 `1185`，增量来自 `1252`；`latest_quote` 不得用于合成权威 OHLC/Volume。Quote/Profit/Kline 订阅均使用 `SNAPSHOT_LOADING -> REPLAYING -> LIVE` 屏障，只回放快照水位之后的增量。

## 5. 元数据字段

| 字段 | 含义 |
| --- | --- |
| `Version` | 元数据版本，当前为 1。 |
| `HeaderSize` | 编码头长度，当前为 32 字节。 |
| `SourcePlugin` | 来源插件，对应 `EN_PLUGIN_ID`。 |
| `NotifyMode` | Best Effort、Reliable、Snapshot 或 Control。 |
| `NotifyAction` | Created、Updated、Deleted、StateChanged 或 Reset。 |
| `PayloadLen` | 正文字节数。 |
| `Sequence` | 当前发布者的关联序号；正式 `1211` 两跳都要求非 `0`。 |
| `TimestampMs` | Unix 毫秒时间戳。 |

可靠通知的持久化、拉取和 ACK 由 MtEventService `1172-1175` 与 JetStream 提供，SourceEpoch/SourceSequence 由 MtTradeService 事件信封提供；这些能力不由 32 字节通知元数据头自动产生。在线 `Publish` 仍只是扇出通道，不能替代 durable consumer。
