# TradingTerminal V3 第一阶段平替 V2 收尾计划（唯一验收依据）

## 2026-08-06 Quote/Event 第一阶段边界修正

- 第一阶段固定为单个 MtQuoteService 实例，每个 `Version+No` 只允许一条 `QUOTE_PUMPING` 物理连接；不启用 Cluster、NATS KV、Owner 竞争、实例接管、行情主备或自动回切。
- Quote 只负责 MT4/MT5 初始化、连接、订阅、Tick 最小校验、深拷贝、进程内 FIFO、SourceEpoch/Sequence、`1211` 发布和 `1124` 定向心跳。
- Quote 已删除 WAL、快照、时间偏移、UTC 转换、`TIME_QUERY`、`1122/1123/1182` 调用、OpenPrice、TickStat、M1 和归档职责。程序崩溃或机器重启期间的 Tick 不提供恢复承诺。
- `queueCapacity=0` 表示 Quote 运行期间不因容量主动淘汰；正数只允许 `128-1000000`，满载时淘汰最旧 Tick。Event 使用独立容量，0 不主动淘汰，正数范围为 `128-10000000` 且满载淘汰最旧 Tick。
- Quote Tick 内部协议重置为 v1，只承载来源、Epoch/Sequence、Symbol、Bid/Ask/Last、Volume、Flags、原始服务器时间和接收时间；旧开发态 v3-v6 不兼容读取。
- Event 第一阶段固定单实例：严格校验 Quote `1211` 三层元数据，按来源固定分片，拒绝重复/乱序并记录 Epoch/Sequence 缺口，再原样本地 Ice 扇出；`1251/1252` 只接受 Derive 来源。Cluster 和 Core NATS Broadcast 禁用。
- Event 可靠链继续提供单节点、`replicas=1` 的 `1172-1175` JetStream，并新增 `1176` 定向心跳。Derive、Query 和 Gateway 的完整消费者迁移仍是端到端阻断项。
- 高可用、多个 Quote 实例、Owner/Fencing、同节点多行情源优先级和自动切换全部进入第二阶段。现有代码继续编译，但第一阶段 XML 不配置生效的 `<Cluster>`，并固定 `sourceFailoverEnable="0"`。
- 本次改造已完成 Quote、六服务和协议测试构建，以及 dev/test 全量与增量打包验证。真实 MT、IceGrid、Event 和消费者联调完成前，状态保持“可编译、可单测，不可生产平替”。

## 4. 统一动态时间权威（旧 Quote Owner 方案，已废止）

本节保留 2026-08-01 的历史设计记录，不再表示当前运行边界。第一阶段 Quote 不维护时间偏移、不执行 UTC 转换、不处理 `1123`，Query/Trade/Derive 的替代方案需要在各自后续改造中落地。

### 4.1 基本原则

- MtQuoteService 是六服务中唯一的运行时间权威，每个 `Version+No` 独立维护时间状态，禁止跨节点复用偏移。
- MT 服务器时区、UTC 偏移或冬夏令状态发生变化时，六个服务均不重启，通过可靠通知和周期快照自动同步。
- 所有 HTTP、WebSocket、内部权威事件和本地业务文件中的业务时间统一保存 UTC0；服务器本地时间只允许存在于 MT SDK 调用边界。
- Windows `timeZoneId` 提供历史和未来日期的动态时区规则，MT 实时测量负责确认服务器当前实际偏移和真实切换。
- 已持久化的实际切换记录优先于 Windows 推算规则，解决交易服务器实际切换时间与标准规则不一致的问题。

### 4.2 公共协议

- 新增 `1123 EN_PLUGIN_FUNC_QUOTE_TIME_SNAPSHOT`，六个服务均可查询全部或指定 `Version+No` 的时间状态。
- 新增可靠通知 `1244 EN_PLUGIN_NOTIFY_SERVER_TIME_CHANGED`，由 MtEventService 持久化、重投和 ACK。
- 时间状态至少包含：
  - `Version/No/TimeZoneId`。
  - MT 配置的标准偏移、当前实际偏移和 Daylight 状态。
  - `AuthorityEpoch/Generation`。
  - `EffectiveUtc/SampledUtc/ValidUntilUtc`。
  - `SyncState/ChangeReason`。
- `AuthorityEpoch` 标识一次时间权威生命周期；`Generation` 在同一 Epoch 内单调递增，防止重启、乱序或旧事件覆盖新状态。
- Quote Tick、M1、交易和查询相关 Binary 正文携带时间代次；消费者遇到未知新代次时先调用 `1123` 校准，不使用旧偏移继续计算。
- 公共错误表增加 `MT_TIME_NOT_READY`、`MT_TIME_STALE`、`MT_TIME_ZONE_INVALID`、`MT_TIME_SYNC_MISMATCH` 和 `MT_TIME_INVALID`，错误描述使用详细英文。

### 4.3 MtQuoteService 检测和发布

- 每个启用的 `Version+No` 配置 Windows `timeZoneId`，例如 `E. Europe Standard Time`。
- MT5 订阅 `IMTConTimeSink`：
  - `OnTimeUpdate` 检测 `TimeZone/Daylight/DaylightState` 变化。
  - `OnTimeSync` 触发立即重新采样。
  - 后台仍定时执行 `TimeGet + TimeServerRequest`，避免漏掉 SDK 回调。
- MT4 每 30 秒执行 `ManagerCommon/CfgRequestCommon + ServerTime`，比较 `timezone`、`timezone_real`、`daylightcorrection` 和实际服务器时间。
- 采样使用 API 调用前后 UTC 中点计算偏移；拒绝 RTT 超限、偏移越界和异常非分钟级结果。
- 新状态连续确认两次后才生效，并严格按以下顺序处理：
  1. 原子保存时间状态和切换记录。
  2. 递增时间代次。
  3. 写入可靠本地 outbox。
  4. 通过 MtEventService 提交 `1244`。
  5. 更新 Quote 当前原子快照并使用新偏移转换后续 Tick。
- Event 暂时不可用时持续重投 outbox，不得丢失时区变化。
- 默认参数：
  - `timeSyncIntervalMs=30000`。
  - `timeSyncMaxStaleMs=180000`。
  - `timeSyncConfirmSamples=2`。
  - `timeSyncMaxRttMs=2000`。
  - `timeReconcileIntervalMs=60000`。

### 4.4 时间配置热更新

- `timeZoneId` 只在 MtQuoteService 配置，Query、Trade、Derive 删除重复的静态 `serverTimeOffsetSeconds` 配置。
- Quote 定时检查 XML 的时间配置指纹，只热加载 `timeZoneId` 和时间同步参数；账号、地址、队列等其他配置仍按正常服务重启流程生效。
- 新时区 ID 必须先通过 Windows 动态时区 API 校验；非法配置保留旧状态并记录详细英文错误。
- 热更新成功后更换 `AuthorityEpoch`、生成新快照并发布 `1244`，其他服务无需重启。
- MT 服务器自身修改时区时无需修改 XML；MT5 回调或 MT4/MT5 定时采样自动发现并同步。

### 4.5 六服务同步职责

- **MtQuoteService**：产生、持久化和发布权威时间状态，负责实时服务器时间到 UTC0 的转换。
- **MtEventService**：可靠保存和分发 `1244`，维护每个节点最新时间状态和 JetStream 消费水位。
- **MtTradeService**：启动先拉取 `1123`，运行期消费 `1244`；交易时段、到期时间、历史时间及回调时间均使用对应代次转换。
- **MtQueryService**：使用时间状态转换历史查询窗口、订单成交时间、Session 和 K线服务器周期边界。
- **MtDeriveService**：按时间代次处理 Tick、M1、日线边界、归档和 Profit；时区切换不得重复或丢失分钟线。
- **MtGatewayService**：不执行时区换算，但保存各节点最新时间代次，用于健康监控、请求路由和 `/server_info` 诊断。
- 六服务在启动、重连以及每 60 秒调用 `1123` 对账；`1244` 负责低延迟通知，`1123` 负责漏通知后的最终一致。
- `1101/1152` 增加时间同步状态、Epoch、Generation 和最后同步时间。Gateway 发现后端代次落后时，将时间相关接口标记为暂不可用，直到完成校准。

### 4.6 转换和降级规则

- 当前实时数据使用 MT 实测偏移，历史数据按目标日期的 Windows 动态时区规则转换。
- UTC0 转服务器时间按目标 UTC 时刻选择对应偏移。
- 服务器时间转 UTC0 遇到秋季重复小时，固定选择较晚的标准时间实例。
- 遇到春季跳过的无效服务器时间，返回 `MT_TIME_INVALID`，不得自动平移。
- `/bars` 和本地文件保存 UTC0；D1/W1/MN1 按服务器日历边界聚合，冬夏令切换日允许为 23 或 25 小时。
- MT4 W1 保持服务器周一开始，MT5 W1 保持服务器周日开始。
- 时间状态超过 `timeSyncMaxStaleMs` 后，Quote 停止发布无法可靠校时的新 Tick，Trade、Query、Derive 的时间相关操作返回明确错误。

## 5. 六服务业务收尾

### 5.1 MtGatewayService

- 通过独立兼容校验器为 30 个接口实现 Object/Array 根节点、Token/Login、必填、范围、互斥项、分页及空数据校验；真实黄金样本发现的差异必须继续在该模块修复。
- `/server_info` 只允许 `Version/No/WebUserStats` 契约字段，响应只暴露 V2 业务结构，并仅在显式请求时补充本实例 Web 统计。
- 补齐 Query/Trade 全部 Binary 响应到 V2 JSON 的字段和错误转换。
- Quote、Symbol、Profit、Order、Position、Deal、User、Kline 八类 Web Topic 均实现初始快照和实时增量。
- 将 `1225` 转换为 Web `10004`，其他公开业务事件转换为 `10002`，不向前端暴露内部 `11xx/12xx`。
- 完成连接代次、固定分片发送、空闲回收、慢连接关闭和断线后的订阅及 Profit 状态释放。

### 5.2 MtQuoteService

- 每个 `Version+No` 第一阶段只创建一条 `QUOTE_PUMPING` 连接，完成 MT4/MT5 初始化、订阅、原连接重连和来源健康状态。
- SDK 回调只做 Tick 最小校验和深拷贝；Manager 在来源 FIFO 中分配 SourceEpoch/Sequence，并通过 `1211` 发布 Quote Tick Binary v1 原始行情。
- `queueCapacity=0` 时运行期间不因容量淘汰；正数模式淘汰最旧 Tick，并通过 `1124` 暴露队列、重连、淘汰和发布失败计数。
- Quote 不实现快照、WAL、时间偏移、OpenPrice、TickStat、M1、归档或历史补数；相关职责由 Derive/Query 后续落地。

### 5.3 MtTradeService

- 对齐 `1132-1142` 的全部 V2 请求字段、返回字段、批量部分失败和 MT4/MT5 差异。
- 完成余额、权限、保证金、交易时段、Stops Level、组、品种、报价新鲜度和 MT4 `MarginDivider` 校验。
- 接入真实 MT4/MT5 Main、Pumping 和 Dealer 回调，维护 RequestId、超时待确认、最终状态及重启对账。
- MT4 开仓不产生 Deal；平仓产生持仓删除和成交新增，部分平仓及 CloseBy 不得重复推送。
- 命令执行成功与事件投递结果解耦；文件幂等和 outbox 在第一阶段继续保留。

### 5.4 MtQueryService

- 建立独立普通查询池和历史查询池，实现 `1153-1155`、`1158-1164`，删除正常业务中的 `HandleUnavailableMt`。
- 完成 MT5 订单、持仓和成交的 `Offset/Limit` 分页以及 MT4 历史查询 UTC0 窗口转换。
- `/bars` 使用 `HISTORY_QUERY` 连接池，合并固定宽度校验文件、MT4/MT5 Chart 回源和 Derive 实时 M1；完成原子替换、损坏隔离、重启恢复和本地选择分页。缺口范围持久化、仅回源缺失区间和 V2 迭代尾部分页仍需由真实差分确认并继续收尾。
- 历史时间转换使用 `TimeZoneId` 对目标日期解析 Windows 动态规则；春季跳过小时拒绝，秋季重复小时选择较晚标准时实例，MT4 W1 从周一、MT5 W1 从周日开始。Broker 自定义历史切换记录仍需真实环境验证。
- `1167` 冻结并分页返回账户、持仓、品种、组及汇率权威状态，保证 SnapshotId 和 EventSequence 一致。
- WatchList、Chart 完成 PostgreSQL 事务、并发更新、表结构校验和 V2 错误兼容。

### 5.5 MtEventService

- `1211` 严格校验 Quote 来源、BestEffort/Updated、ClientData 外层和 Quote v1 正文一致性；同一 `Version+No` 固定分片并按 Epoch/Sequence 检查连续性。
- 工作线程不修改正文，只以 Event 身份本地 Ice 扇出；`1251/1252` 只接受 Derive 来源，第一阶段三类在线通知均不进入 NATS。
- `queueCapacity=0` 不主动容量淘汰；正容量满载淘汰最旧 Tick，并通过 `1103/1176` 暴露队列、拒绝、缺口、扇出和失败计数。
- `1172-1175` 使用单节点、`replicas=1` JetStream；Trade 产生交易/配置事件，Query 后续产生 `1244` 时间事件。
- 第一阶段 Cluster 和 Broadcast 均关闭；Core NATS 多 Event 广播和三副本 JetStream 只保留为第二阶段配置注释。

### 5.6 MtDeriveService

- 先缓冲可靠增量，再安装 Query `1167` 快照，只应用水位后的事件并持久化消费者进度。
- 实现 MT4/MT5 收益、合约大小、方向、账户币种和交叉汇率规则；缺失汇率返回不可计算状态。
- 迁移 Profit 汇率需求回收、公平调度、QPS 限制、失败退避和内存稳定性规则。
- `1184` 返回真实初始收益快照，租约有效期间发布 `1251`；恢复完成前保持 `BOOTSTRAPPING`。
- 保留无损 Tick、M1、`1182/1185/1252`，补齐长期归档、历史缺口恢复和重启检查点。

- 验证旧事件、重复事件、乱序事件、Event/Quote 重启、状态文件损坏和网络分区不会回退时间代次。
- 验证跨冬夏令时的历史订单、成交、Session、交易校验、Profit、M1/D1/W1/MN1 和归档结果。

### 6.3 恢复和外部依赖

- 验证多 `Version+No`、Quote 冷启动、节点断线、服务晚启动、进程重启及 WAL/快照损坏恢复。
- 验证 PostgreSQL 事务、JetStream 重启、未 ACK 重投、重复事件、DLQ、积压上限和消费者恢复。
- 六服务连续运行至少 72 小时，期间执行 MT、PostgreSQL、JetStream、IceGrid、网络抖动和时区切换故障注入。
- 要求无崩溃、无不可恢复积压、无重复交易、无持续内存增长，依赖恢复后能够自动回到 READY。
- 分别强制结束六个 EXE，连续三轮验证 IceGrid 在 30 秒内自动恢复，且不存在重复进程、端口冲突或重复 Adapter 注册。
- 关闭 Quote、Trade、Derive Owner、整个业务 Node 和业务网络，验证 20 秒内接管、旧 fencing 写入被拒绝、无双主和无不确定交易自动重试。
- 停止一个 NATS 节点时业务继续；失去两个节点时状态型服务在 10 秒内 fail closed，恢复 quorum 后只以 Standby 身份重新竞争。
- 停止 Registry Master、任一 Nginx、任一 Gateway/Event/Query，验证发现、统一入口、WebSocket 重连、订阅恢复和快照补齐。

### 6.4 性能门槛

- 在相同硬件和相同负载下建立 V2 基线；V3 吞吐不得低于 V2，P95 不得高于 V2 的 110%，P99 不得高于 V2 的 120%，就绪期间成功率不低于 99.9%。
- 测量 Tick 接入到 Web、交易提交到最终确认、Query 和 K线请求的 P50/P95/P99，不允许仅以配置连接数作为容量结论。
- 行情进入 MtQuoteService 到 WebSocket 写入的 P99 不超过 200ms，收益变化进入 Derive 到 WebSocket 写入的 P99 不超过 500ms。
- 第一阶段保留文件幂等和文件 outbox，但不再允许全服务幂等锁串行；当前 64 分片实现仍必须通过 V2 非退化性能门槛。
- 使用 10 万 WebSocket 连接执行 N+1 测试，移除一台业务机后剩余节点继续承载，就绪期间成功率不低于 99.9%。

## 7. 灰度切换与回滚

- Query、Quote 和 Web 行情先与 V2 并行运行并比较至少 5 个交易日，且必须覆盖一次可控的时区切换模拟。
- Trade 使用测试账户完成全流程，再按账户白名单逐步切换；禁止把同一交易请求同时提交给 V2 和 V3。
- 依次按 5%、25%、50%、100% 扩大 V3 流量，每阶段检查错误率、延迟、事件积压、时间代次和数据差异。
- 保留 V2 可执行文件、配置和回滚脚本；任一核心接口数据不一致、时间错位、交易状态丢失或持续超出性能基线时立即回退。
