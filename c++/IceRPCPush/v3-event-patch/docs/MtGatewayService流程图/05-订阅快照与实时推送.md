# 订阅、快照与实时推送

## 1. 范围与状态

描述八类 Topic 的订阅、快照增量屏障、实时事件过滤、固定 Sender 分片和慢连接处理。源码及协议测试已完成；真实链路无丢失窗口、行情 P99 和收益 P99 待 dev/test 与生产验收。

| 项目 | 内容 |
| --- | --- |
| 输入 | Web `10002` 订阅/退订、Event `1211/122x/124x/125x` 通知 |
| 输出 | 初始快照、Web `10002/10004` 实时消息、重同步连接关闭 |
| 线程/队列 | SocketServer 控制回调、Web 扫描线程、固定 Sender 线程及每分片 Quote/Profit/Normal 队列 |
| 所有权 | SessionManager 拥有订阅状态和反向索引；PushDispatcher 拥有批量任务、共享正文和待发字节表 |

| Topic | 初始数据 | 实时数据 |
| --- | --- | --- |
| Quote | Derive `1185 OpenPrice-only` 后 Quote `1122` | Event `1211` |
| Symbol | Query `1153` | Event `1241` |
| Profit | Derive `1184` | Event `1251` |
| Order | Query `1162` | Event `1221` |
| Position | Query `1163` | Event `1223` |
| Deal | Query `1164` | Event `1222` |
| User | Query `1158` | Event `1224/1242` |
| Kline | Derive `1185` | Event `1252` |

## 2. 订阅与快照增量屏障

~~~
graph TD
    A["收到10002订阅请求"] --> B["校验认证主体 Topic Version No Login Symbol"]
    B --> C["状态置为SNAPSHOT_LOADING"]
    C --> D["先登记反向索引并有界缓冲增量"]
    D --> E["立即返回订阅控制应答"]
    D --> F{Topic初始来源}
    F -- Quote --> G0["异步调用Derive Owner 1185 OpenPrice-only"]
    G0 --> G["安装确认OpenPrice后异步调用Quote Owner 1122"]
    F -- Profit --> H["异步调用Derive Owner 1184"]
    F -- Kline --> I["异步调用Derive Owner 1185"]
    F -- 其他 --> J["异步调用Query对应接口"]
    G --> K["回调校验Generation Revision和Attempt"]
    H --> K
    I --> K
    J --> K
    K --> L["原子安装Epoch和快照水位并置REPLAYING"]
    L --> M["固定Sender先发送10002快照"]
    M --> N["丢弃水位内重复并按序回放水位后增量"]
    N --> O["原子切换LIVE"]
    K --> P{超时溢出Epoch变化或序号缺口}
    P -- 首次 --> Q["使旧回调失效并重试一次"]
    P -- 再次 --> R["标记RESYNC_REQUIRED并关闭连接"]
    D --> S["Profit需求集合变化"]
    S --> T["扫描线程提交1183 REPLACE租约"]
~~~

快照回调必须同时匹配连接代次、订阅修订号和尝试次数。退订、断线、重连或二次快照会使旧回调失效，旧快照不能覆盖新 Tick。

## 3. 固定 Sender 批量扇出

~~~
graph TD
    A["收到Event的12xx通知"] --> B["每个事件只解码一次Binary"]
    B --> C["映射Topic和10002或10004"]
    C --> D["按Topic Version No Login Symbol查询反向索引"]
    D --> E["只编码一次共享不可变JSON正文"]
    E --> F["按Connection Generation稳定映射固定Sender"]
    F --> G["同Sender目标按fanoutBatchTargets切块"]
    G --> H{队列类别和来源模式}
    H -- raw_tick Quote --> I["Quote FIFO 不去旧不合并不节流"]
    H -- latest_quote --> J["按Version No Symbol替换整组目标槽"]
    H -- Profit --> K["Profit队列"]
    H -- 其他 --> L["Normal队列"]
    I --> M["Sender按统一入队序号维持单连接顺序"]
    J --> M
    K --> M
    L --> M
    M --> N{单连接待发字节持续超限或Sender拒绝批次}
    N -- 是 --> O["标记RESYNC_REQUIRED并按Generation关闭"]
    N -- 否 --> P["再次校验Generation后写Socket"]
~~~

`quoteMinIntervalMs=0` 为 `raw_tick`；正数为按 `Version+No+Symbol` 合并的 `latest_quote`。后者只适合价格展示，不能用于合成权威 OHLC/Volume。

Gateway 后续从 `1185/1252` 按 Broker 日期和日初确认位维护每品种 OpenPrice，并在 `1211` Quote v1 增量转换时合并。Quote v1 不携带 Open/Close/Low/High/PrevClosed 扩展价格；消费端尚未取得 Derive/Query 的确认状态时，这五个兼容字段保留为 `0`，不得从原始 Tick 伪造。

## 4. 行情缺口恢复

~~~
graph TD
    A["收到1211"] --> B["读取正文SourceEpoch和IngressSequence"]
    B --> C{与来源已接受水位连续}
    C -- 重复或乱序 --> D["忽略旧Tick"]
    C -- 连续 --> E["按订阅状态缓冲或LIVE扇出"]
    C -- Epoch变化或缺口 --> F{quoteMinIntervalMs}
    F -- 0 raw_tick --> G["关闭该来源全部连接并要求重连快照"]
    F -- 正数 latest_quote --> H["暂停LIVE并回到SNAPSHOT_LOADING"]
    H --> I["当前Tick先进入新屏障缓冲"]
    I --> J["重新调用1185 OpenPrice-only后再调用1122恢复"]
~~~

`10004` 继续只承载交易源状态，不表示行情缺口。

## 5. 停止与资源释放

~~~
graph TD
    A["服务停止"] --> B["Dispatcher停止接收新批次"]
    B --> C["唤醒全部Sender"]
    C --> D["排空已接受任务"]
    D --> E["关闭仍持续超限的慢连接"]
    E --> F["join全部Sender线程"]
    F --> G["清空三类队列 合并槽 PendingBytes和统计"]
~~~
